## 2. 三种模式

模式常量来自 `RunDemoEngine`：`MODE_DYNAMIC = 0` / `MODE_CONSTANT = 1` / `MODE_CURVE = 2`（`RunDemoEngine.ets:32-34`）。

界面上的分段控件 **只有两段**：`['动态检测', '预设']`（`Player.ets:88`）。「预设」是一个入口，进去之后走**曲线**还是**恒速**由「有没有选中曲线」决定：

```ts
// Player.ets:1468-1473
private selectSegment(seg: number): void {
  const target: number = (seg === 0)
    ? MODE_DYNAMIC
    : (this.hasCurve ? MODE_CURVE : MODE_CONSTANT);
  this.switchMode(target);
}
```

| 模式 | 控制律 | 倍速 | 说明 |
| --- | --- | --- | --- |
| 动态检测 | FOLLOW（闭环） | 实测步频 ÷ 歌曲 BPM | 会启 native 步频管线；步频抖，倍速平滑 τ=2s |
| 预设 · 恒速 | PRESET（开环） | 目标步频 ÷ 歌曲 BPM | 不读脚步，音乐是节拍基准 |
| 预设 · 曲线 | PRESET（开环） | 曲线(运动时间) ÷ 歌曲 BPM | 点之间线性插值，走完保持最后一档 |

关键产品决策（`Player.ets:1350-1359`）：**只有动态模式才启步频管线**。恒速/曲线是完全开环的，native 侧虽然保留 PRESET 控制律 + PhaseTrim，但当前不从这里启用。

- 曲线来源：曲线列表里选中的那条（AppStorage 的 `ACTIVE_CURVE_KEY`，0 = 恒定BPM）。`aboutToAppear` 里读盘、取点、算纵轴量程，装进 `engine.setCurvePoints()`（`Player.ets:278-312`）。**先选后用**，播放中不换。
- 动态模式的步频源由设置页决定：`StepSource.SOURCE_SIM`（native GaitSim 模拟）或 `SOURCE_REAL`（加速度计）。当前代码里真实源仍显示「未接线」（`Player.ets:841-843`）。

## 3. 进度条与播放控制

- 进度条是**真的 Slider**，value 绑 `posSec`、max 绑 `durSec`、`step: 0.1`（`Player.ets:440`）。
- 拖动期间 `seeking = true` 由 UI 接管，避免 tick 把滑块拽回去；松手时同时 `engine.seek(value)` 和（开了真实音频时）`native.seek(value)`（`Player.ets:445-458`）。
- 上一首 / 下一首目前只动页面估算的时间轴：上一首 `engine.seek(0)`，下一首 `engine.seek(durSec - 1)`（`Player.ets:475-503`）。**注意它们没有同步调 `native.seek`**，真实音频开启时这是已知缺口。
- 打开真实音频后，页面每 ~200ms 轮询 `native.status()`，把 `posSec` 回填给 `engine.syncPosition()`，修掉页面自积分造成的拍相位漂移（`Player.ets:1533-1557`）。

## 4. 接真实音频 / native 链路

### 4.1 曲库与歌单

`loadSongList()`（`Player.ets:1036-1086`）：

- 歌单来自 `PlayListStore.loadAll()`，当前选中的歌单下标来自 `AppStorage` 的 `ACTIVE_PLAYLIST_KEY`。
- 选了歌单 → 按歌单里保存的 **filename** 顺序从 `song_data.json` 取条目（`resolvePlaylistEntries`，filename 为空的老数据按歌名兜底）；没选歌单 → 整库。
- 曲库里没有当前记的歌就取第一首；空库退回 `engine.setSong(null)` 的演示默认值。

### 4.2 native 播放

`startNative()`（`Player.ets:1578-1618`）：

1. `native.setStretchEngine(getStretchEngine())` —— 起播前把「变速引擎」选择（0 = SignalSmith Stretch / 1 = 系统 Audio Kit）下发给 native。
2. 优先播 `song_data.json` 指向的真实文件（`native.preparePath(songPath)`）。
3. 没有真实文件时才退回内置演示音源 `NATIVE_RAW = 'LostMemory.m4a'`（`Player.ets:68`）。

`NativeAudio`（`ets_libs/NativeAudio.ets`）目前用到的接口：`music_play`、`music_prepare`、`music_start`、`music_pause`、`music_resume`、`music_cancel`、`music_seek`、`music_set_volume`、`changeSpeed`、`musicGetStatus`、`setStretchEngineMode`。其中 `music_play` 的 progress 回调签名还在，但 native 侧那段回调**仍未启用**，所以进度不靠它、改走 `musicGetStatus`（`NativeAudio.ets:146-148, 307-317`）。

### 4.3 预解码 + 接歌硬切（S2/S3）

- 提前量 `PREPARE_AHEAD_SEC = 30s`：快到结尾时先 `music_prepare` 解码下一首（`Player.ets:65, 1227-1252`）。
- 只有 `pendingReady()`（状态到 `prepared/ready`）才允许切，否则现场加载兜底（`Player.ets:1186-1192, 1280-1299`）。
- `doHardCut()` 用 native 实测的 `startLatencyMs` 决定提前多久按 `music_start`，再用 `music_set_volume` 给旧会话做音量淡出，做到「不断音也不双声」（`Player.ets:1273-1337`）。
- 临近结尾那 2.5 秒会把轮询从 5Hz 提到每帧（`Player.ets:1706-1718`）。

### 4.4 native 步频管线

`startPipeline()`（`Player.ets:1350-1382`）只在动态模式执行：

```ts
stepPipelineSetChaseDelayWindow(getChaseDelaySec());   // 起步延迟校正窗口（0 = 关闭）
if (this.stepSource === SOURCE_REAL) {
  stepSensorStart(this.songBpm, this.firstBeat, 0, 0.0);  // 真实加速度计，由 StepSensor 攒批喂
  if (!stepSensor.start()) { stepSensorStop(); return; }
} else {
  stepPipelineStart(this.stepScenario, this.songBpm, this.firstBeat, 0, 0.0);  // 模拟源
}
```

`pollPipeline()` 解析 `stepPipelineStatus()`，用 `multiplier` 覆盖页面倍速（`Player.ets:1398-1415, 1673-1679`）。模拟场景 0~5 与 native `gaitsim::scenarios::at()` 对齐（`StepSource.ets:20-31`）。

### 4.5 变速引擎

`StretchEngine.ets` 存全局选择，`startNative` 起播前调 `setStretchEngineMode`。native 里 0 = 自研 LiveStretchPlayer（Renderer 倍速固定 1.0），1 = 系统 Audio Kit（OH_AudioRenderer_SetSpeed，内部 Sonic）。算法参数设置页可切，并提供 `getStretchEngineStatus()` 自检。

### 4.6 还没接的（见 `index.d.ts`）

- `music_play` 的 progress 回调仍未启用；页面进度靠 `musicGetStatus().posSec` 回填。
- native 还没有统一的 `session_*` 会话接口；`RunDemoEngine` 仍是位置/拍相位的主时间轴。
- 上一首/下一首没有下行到 `native.seek`（第 3 节）。
- 真实传感器源（`SOURCE_REAL`）在页面上仍按「未接线」处理。

## 5. 拍点光效：从「无限循环动画」改成「拍相位驱动」

旧版光效是一个按 BPM 自由跑的无限循环动画。现在改成**由歌曲位置算出的拍相位**驱动：

```ts
// Player.ets:1633-1638（pullGlow，每帧调用）
const s: RunStatus = this.engine.status();
let a: number = 1 - s.beatPhase;
if (a < 0) { a = 0; }
this.pulseOpacity = Math.pow(a, 1.6);
```

拍相位 `phase = frac((pos − firstBeat) / (60/BPM))`（`Player.ets:52-54`），所以**变速时相位依然锁在拍上**。相比旧版无限动画，它同时解决了「拖倍速时闪光乱掉」和「多个循环动画抢同一个属性」两个问题。

性能要点（页面注释 `Player.ets:1620-1624`）：

- `pullGlow()` 每帧只写 `pulseOpacity` **一个** `@State`，ArkUI 只更新光晕那一层；
- 其余十几个 `@State` 只在 `pullStatus()` 里以 ~5Hz 更新；
- 如果每帧去写整组状态，整页 30fps 重绘，在模拟器上就是「卡 + 偶尔空一下」。

光晕本身仍是「和封面同形状的阴影层」：一个同尺寸圆角方块 + `.shadow()`，被封面完全盖住，露出的只有阴影（`Player.ets:337-366`）。

| 常量 | 现在 | 作用 |
| --- | --- | --- |
| `GLOW_SHADOW_RADIUS` | 34 | 光带多宽多柔（现在是常量，页面上没有范围滑块了） |
| `GLOW_ALPHA` | 0.92 | 拍子处的亮度 |
| `glowEnabled` | true | 调试区可开关光效；关掉时 `pulseOpacity` 归 0 |

## 6. ⚠️ 别人极可能也会踩的坑

### 6.1 `Slider` 的 `step` 有硬性范围，越界会被静默降级

官方对 `SliderOptions.step` 的说明：

> **Value range: [0.01, max - min]**
> NOTE: If this parameter is set to a value less than 0 or greater than the value of max, **the default value is used**.

- `step < 0.01` → 不报错、不警告，直接换成默认值 **1**；
- 区间很窄时（比如 `0 ~ 1`）就会只剩两个位置。

旧版本页真实踩过：倍速滑块写 `min: 0, max: 1, step: 0.001`，结果数值只在 `x0.10` 和 `x4.00` 之间跳。现在页面已不用归一化滑块（进度条 `step: 0.1`、步频/目标滑条 `step: 1`），但规则照旧：**任何 `Slider` 都确认一遍 `step >= 0.01` 且 `step <= max - min`**。

### 6.2 无限循环动画不要反复重建

`animateTo(... `iterations: -1`)` 创建的是**挂在属性上的循环动画**。对同一个属性再调一次，就会再挂一个；多个循环不同步地拉扯同一个属性，表现是「闪烁突然变得飞快/完全乱掉」。

**规则**：

- 需要循环动画时，保证同一时刻只有一个在跑；
- 高频事件（滑条 `onChange`、拖拽、定时器）里不要调重启动画的方法；
- 只在离散事件（松手、开关、模式切换）里重启。

本页现在干脆**不用循环动画**：光效每帧按 `beatPhase` 直接赋值（第 5 节）。这也侧面说明：像「跟随节拍闪烁」这种高频、需要随时改相位的效果，用每帧赋值比无限动画更可控。

### 6.3 `Slider` 的 `onChange` 触发非常频繁

`onChange(value, mode)` 在拖动过程中每帧都会来一次，`mode` 有 `Begin / Moving / End / Click` 四种：

- 要做「松手才生效」的事，判断 `mode === SliderChangeMode.End || mode === SliderChangeMode.Click`（进度条就是「拖动时只改 UI、松手才 seek」）；
- 别在这个回调里做重活（重建动画、原生请求、大数组重排）。

### 6.4 八位色是 `#AARRGGBB`，alpha 在前

和 CSS 相反。按透明度动态生成颜色得自己拼（`Player.ets:93-107`）：

```ts
function accentWithAlpha(alpha: number): string {
  let a: number = Math.round(alpha * 255);
  if (a < 0) { a = 0; }
  if (a > 255) { a = 255; }
  let hex: string = a.toString(16);
  if (hex.length < 2) { hex = '0' + hex; }
  return '#' + hex + 'FF6B6B';
}
```

### 6.5 想要「发光」就用阴影，但要知道它的两个特性

- **阴影自动贴着形状走**，是原生高斯模糊，比自己叠渐变省事；
- **阴影是向外扩散的**，会盖到相邻元素上；半径拉大要注意别压住下面的文字；
- 本页把动画放在 `opacity` 上，阴影会跟着一起淡出（强度/范围这些静态属性随便改，互不干扰）。
- 注意：`Stack` 没有 `justifyContent`，居中要用 `alignContent`（`Player.ets:369`）。

### 6.6 用系统符号（`sys.symbol.*`）前先确认名字存在

`$r('sys.symbol.xxx')` 名字写错**不会报错**，只是图标不显示。编译器校验的那张表在：

`<SDK>/openharmony/ets/build-tools/ets-loader/sysResource.js`

本页用到的：`opticaldisc`（专辑占位）、`play_fill` / `pause_fill`、`backward_end_fill` / `forward_end_fill`（上一首/下一首）、`checkmark_square_fill` / `square`（复选框）。

**填充类符号（`xxx_fill`）在单色渲染下可能只剩一个实心块**；要稳妥就用自己拼图形 + 普通符号。

### 6.7 定时器必须在 `aboutToDisappear` 里清掉

页面退出后定时器还在跑的话会持续改状态。本页在 `aboutToDisappear()` 里 `stopTick()`，并一并停掉 native 管线、撤掉预解码会话、`native.stop()`（`Player.ets:325-330`）。

### 6.8 自定义组件的成员名不能和通用属性重名

比如 `enabled`（它是 `CommonMethod` 上的方法），成员同名会报：

```
Property 'enabled' in type 'Xxx' is not assignable to the same property in base type 'CustomComponent'.
```

同类高危名：`id / key / size / direction / align / clip / scale / rotate / translate / opacity / visibility / position / margin / padding / border / width / height / zIndex / gesture / offset`。

本页的真实案例：拍点偏移本来想叫 `offset`，只能改名 `beatOffset`（`Player.ets:177-178`）。（详见 `docs/界面说明_曲线编辑器.md` 的 3.4 节。）
