## 2. 倍速拉杆的两种模式

右上角的分段控件切换，两种模式的**量程和刻度性质完全不同**：

| 模式 | 量程 | 刻度 | 界面显示 |
| --- | --- | --- | --- |
| 纯倍速 | x0.1 ~ x4 | **log2** | `x1.25` |
| BPM | 40 ~ 240 | 线性 | `150 BPM` |

### log2 刻度是怎么做的

`Slider` 本身只有线性刻度，所以倍速模式的滑条 value 存的是**归一化位置 0~1**，真正的倍速由它换算：

```ts
/** 归一化位置 → 倍速（log2 刻度：位置在 log2 上均匀分布） */
function posToSpeed(t: number): number {
  const lo: number = Math.log2(SPEED_MIN);   // log2(0.1) ≈ -3.32
  const hi: number = Math.log2(SPEED_MAX);   // log2(4)    =  2
  return Math.pow(2, lo + (hi - lo) * t);
}
```

好处是 **x0.5 和 x2 离 x1 一样远**，手感对称。位置 `0.624` 正好对应 x1.00（就是默认值 `DEFAULT_SPEED_POS` 那个数，改量程时要跟着重算）。

### 切换模式时数值要对齐

否则用户从 x2.00 切到 BPM 模式会突然变成 150 BPM 之类的怪值：

```ts
// 倍速 → BPM
this.bpmValue = BASE_BPM * this.speedValue();
// BPM → 倍速
this.speedPos = speedToPos(this.bpmValue / BASE_BPM);
```

`BASE_BPM = 150` 是"这首歌的原始 BPM"，两种模式靠它互相换算，所以 **x1.0 ↔ 150 BPM 是一一对应的**。接真实歌曲时这个值要从分析结果里来（见第 4 节）。

## 3. 心跳光效

### 做法：一层同形状的阴影

```ts
// 光晕层：和封面同形状、同尺寸，被封面完全盖住；
// 露在外面的只有它投出的阴影 —— 那就是围着封面的一圈灯带
Column()
  .width(ALBUM_SIZE).height(ALBUM_SIZE)
  .borderRadius(ALBUM_RADIUS)
  .backgroundColor(ACCENT)          // 只用来"投出"阴影，本身被封面挡住
  .shadow({ radius: this.glowRadius, color: accentWithAlpha(GLOW_ALPHA), offsetX: 0, offsetY: 0 })
  .opacity(this.pulseOpacity)       // 唯一被动画驱动的属性
```

**为什么用阴影而不是自己叠几层渐变**：阴影是原生高斯模糊，而且**自动贴着组件的形状走**。封面是圆角方形，阴影就是圆角方形的一圈光，严丝合缝；自己叠层要么是圆的（形状对不上），要么会有分层。

### 闪烁是"突然亮 → 渐暗"

```ts
this.pulseOpacity = 1;   // 先把光瞬间拉到最亮（这一步不带动画）

this.getUIContext().animateTo({
  duration: beatMs,          // 一个拍子的时长，暗下去正好接上下一次亮起
  curve: Curve.EaseOut,      // 先暗得快、尾巴拖得久，更像灯
  iterations: -1,            // 无限循环
  playMode: PlayMode.Normal  // 每轮从动画起点重来
}, () => {
  this.pulseOpacity = 0;
});
```

关键是 `playMode`：

- `PlayMode.Normal` → 每轮跳回起点重来 = **突然亮 → 渐暗**（心跳感）
- `PlayMode.Alternate` → 正反交替 = 渐亮渐暗（呼吸感）

### 可调的量

| 常量 | 现在 | 作用 |
| --- | --- | --- |
| `GLOW_SHADOW_RADIUS` | 36 | 光带多宽多柔（页面上有临时滑块可实时调） |
| `GLOW_ALPHA` | 0.9 | 拍子处的亮度 |
| `GLOW_RADIUS_MIN/MAX` | 0 / 100 | 临时滑块的量程 |

## 4. 接真实播放 / 外部回调要改的地方

### 4.1 替换演示数据

页面顶部一组常量，全部集中在一起：

```ts
const SONG_TITLE: string = 'Crave Wave';
const SONG_ARTIST: string = 'LandRoot';
const SONG_ALBUM: string = '演示专辑';
const DEMO_DURATION: number = 198;   // 秒，3:18
const BASE_BPM: number = 150;        // 这首歌的原始 BPM，两种倍速模式靠它换算
```

接真实歌曲时把它们换成从跳转参数或播放器状态读来的值，`DEMO_DURATION` 换成音频真实时长。

### 4.2 假进度换成真实进度

现在点播放会跑一个 250ms 的定时器（`startTimer`），按当前倍速推进假进度：

```ts
this.timerId = setInterval(() => {
  let next: number = this.progress + TICK_MS / 1000 * this.playRate();
  ...
}, TICK_MS);
```

接上原生播放后，把 `this.progress` 改成由播放器的进度回调更新即可，定时器整段可以删掉：

```ts
music_play(audioPath, (progress: number) => {
  this.progress = progress;   // 进度就交给它
});
```

### 4.3 变速值交给原生引擎

`playRate()` 现在只是用来算假进度，接上播放后**它的返回值正好就是要传给原生引擎的倍速**：

```ts
/** 播放速率：变速关掉就是 1.0 */
private playRate(): number {
  if (!this.speedEnabled) {
    return 1;
  }
  return this.isBpmMode ? this.bpmValue / BASE_BPM : this.speedValue();
}

// 接法：任何改变倍速的地方都顺手下发一次
changeSpeed(this.playRate());
```

### 4.4 光效改成外部回调驱动（推荐方向）

现在光效的节拍来自页面内部的 `effectiveBpm()`（"原始 BPM × 倍速"或"BPM 模式的目标值"），将来应该由外部（原生/播放器）在**每一拍回调一次**来驱动：

```ts
// 1) 原生侧加一个回调接口（示例）
// export const setBeatCallback: (cb: () => void) => void;

// 2) 页面里改成"收到回调就点一次灯"
private onBeat(): void {
  const beatMs: number = Math.max(150, 60000 / this.currentBpmFromExternal);
  this.pulseOpacity = 1;   // 瞬间点亮
  this.getUIContext().animateTo({
    duration: beatMs,
    curve: Curve.EaseOut,
    iterations: 1,           // ← 注意：这里不再是无限循环
    playMode: PlayMode.Normal
  }, () => {
    this.pulseOpacity = 0;
  });
}
```

⚠️ **这么做的时候要注意一点**：每次回调都会新建一个动画，所以

- `iterations` 要从 `-1` 改成 `1`（一次淡出就够，不需要循环）
- 淡出时长要**短于回调间隔**，否则动画还没跑完下一次回调就来了，多个动画会叠在同一属性上（见 5.2）
- 这样改完，倍速/BPM 滑块就**再也不用碰动画了** —— 现在那个"拖倍速时闪光会乱"的问题会自然消失

## 5. ⚠️ 别人极可能也会踩的坑

### 5.1 `Slider` 的 `step` 有硬性范围，越界会被静默降级

官方对 `SliderOptions.step` 的说明：

> **Value range: [0.01, max - min]**
> NOTE: If this parameter is set to a value less than 0 or greater than the value of max, **the default value is used**.

也就是说：

- `step < 0.01` → **不报错、不警告**，直接换成默认值 **1**
- 后果：如果区间本身很窄（比如 `0 ~ 1`），step 变成 1 之后就**只剩两个位置**，滑条只能在两端跳

本页真实踩过：倍速滑块本来写 `min: 0, max: 1, step: 0.001`，结果数值只能在 `x0.10` 和 `x4.00` 之间跳，看着像"刻度错了"，其实是 step 被降级。

**自查**：任何 `Slider` 都确认一遍 `step >= 0.01` 且 `step <= max - min`。区间是 0~1 这种小范围时，老实写 `0.01`。

### 5.2 无限循环动画不要反复重建

`animateTo(`... `iterations: -1)` 创建的是一个**挂在属性上的循环动画**。对同一个属性再调一次 `animateTo`，就会再挂一个循环上去。多个循环彼此不同步地拉扯同一个属性，表现是"闪烁突然变得飞快/完全乱掉"。

**规则**：

- 需要循环动画时，保证**同一时刻只有一个在跑**
- 高频事件（滑条的 `onChange`、拖拽、定时器）里**不要**调重启动画的方法
- 只在离散事件（松手、开关、模式切换）里重启

本页的做法是 `restartPulse()` 里带一个节流（周期变化小于 8ms 就直接返回），并且**滑条的 `onChange` 只改数值、不碰动画**。

### 5.3 `Slider` 的 `onChange` 触发非常频繁

`onChange(value, mode)` 在拖动过程中每帧都会来一次，`mode` 有 `Begin / Moving / End / Click` 四种。所以：

- 要做"松手才生效"的事，判断 `mode === SliderChangeMode.End || mode === SliderChangeMode.Click`
- 别在这个回调里做重活（重建动画、发网络/原生请求、大数组重排）

### 5.4 八位色是 `#AARRGGBB`，alpha 在前

和 CSS 相反。要按透明度动态生成颜色时得自己拼：

```ts
/** 强调色 + 指定透明度 → '#AARRGGBB' */
function accentWithAlpha(alpha: number): string {
  let a: number = Math.round(alpha * 255);
  if (a < 0) { a = 0; }
  if (a > 255) { a = 255; }      // 超出会被静默截断，不如自己夹住
  let hex: string = a.toString(16);
  if (hex.length < 2) { hex = '0' + hex; }
  return '#' + hex + 'FF6B6B';
}
```

### 5.5 想要"发光"就用阴影，但要知道它的两个特性

- **阴影自动贴着形状走**，是原生高斯模糊，比自己叠渐变省事得多（本页光效就一层阴影）
- **阴影是向外扩散的**，会盖到相邻元素上；半径拉很大时要注意别压住下面的文字
- 本页实测：把动画放在 `opacity` 上，阴影会跟着一起淡出（所以强度/范围这两个静态属性可以随便改，互不干扰）

### 5.6 用系统符号（`sys.symbol.*`）前先确认名字存在

`$r('sys.symbol.xxx')` 里的名字写错**不会报错**，只是图标不显示。编译器校验的那张表在：

`<SDK>/openharmony/ets/build-tools/ets-loader/sysResource.js`

本页用到的：`opticaldisc`（专辑占位）、`play_fill` / `pause_fill`、`backward_end_fill` / `forward_end_fill`（上一首/下一首）、`checkmark_square_fill` / `square`（复选框）。

另外**填充类符号（`xxx_fill`）在单色渲染下可能只剩一个实心块**，看不出细节；要稳妥就用自己拼图形 + 普通符号（本页复选框就是这么做的）。

### 5.7 定时器必须在 `aboutToDisappear` 里清掉

页面退出后定时器还在跑的话会持续改状态。本页的做法是 `timerId` 记下来，`aboutToDisappear` 里 `clearInterval`。

### 5.8 自定义组件的成员名不能和通用属性重名

比如 `enabled`（它是 `CommonMethod` 上的方法），成员同名会报：

```
Property 'enabled' in type 'Xxx' is not assignable to the same property in base type 'CustomComponent'.
```

同类高危名：`id / key / size / direction / align / clip / scale / rotate / translate / opacity / visibility / position / margin / padding / border / width / height / zIndex / gesture`。
（详见 `docs/界面说明_曲线编辑器.md` 的 3.4 节）
