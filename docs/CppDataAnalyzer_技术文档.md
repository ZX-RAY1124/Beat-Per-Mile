## 1. 它解决什么问题

给一首歌的**节拍时间戳序列**（由 madmom 或 Essentia 检测得到），回答两个问题：

1. **这首歌的速度是多少？**（而且速度可能一直在变）
2. **哪些时间段速度是稳定的？每段的速度是多少、在往哪个方向变？**

输出是一串"**速度段落**"，每段带起始 BPM、BPM 变化趋势和置信度。

为什么需要它：跑步电台要让音乐节奏跟随步频，就必须知道"当前这首歌在**此刻**是多少 BPM、
接下来是渐快还是渐慢"。对一首全程匀速的歌，一个数字就够；但现实中的歌常见：

- 前奏慢、副歌快（**分段变速**）
- 渐快（ritardando / accelerando，例如 `Trina Lydia - BPM = BPM + 1` 这种整首歌持续加速的曲子）
- 检测器把两拍并成一拍、或把一拍拆成两拍（**层级混叠**，会让拍间隔忽长忽短）

这三件事分别对应本算法的三个部件：**聚类归一化**（对付混叠）、**二次回归**（对付渐变）、
**递归分裂**（对付分段）。

## 2. 输入输出

**输入**：节拍表 CSV（与 `madmom_to_CSV.py` / `essentia_to_CSV.py` 输出格式一致）

```
# song=Protocol - 塞壬唱片-MSR
# model=madmom
0.5
1.04
1.55
...
```

**输出**：一串 `Paragraph`，每个段落含

| 字段 | 含义 |
|---|---|
| `start` / `end` | 段落起止时间（秒） |
| `bpm_start` | 段落**起始** BPM |
| `bpm_trend` | BPM 每拍变化量（正=渐快，负=渐慢） |
| `r2` / `rmse` | 拟合优度 / 残差标准差 |
| `a`, `b`, `c` | 二次模型系数（可用于逐拍求 BPM） |
| `beat_count` | 段落内节拍数 |

## 3. 处理流程总览

```
                   节拍表 CSV
                       │
                       ▼
              ┌─────────────────┐
              │ 1. 拍间隔 Δtᵢ   │   Δtᵢ = t(i+1) - t(i)
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │ 2. 聚类归一化    │   k-means 把 Δt 分成 2 簇
              │   （消除混叠）   │   每簇归到整数倍 1/2/3/4，除以倍数
              └────────┬────────┘   得到"均匀化"的节拍序列 t'(n)
                       ▼
              ┌─────────────────┐
              │ 3. 二次回归      │   t'(n) = a·n² + b·n + c
              │   （拟合变速）   │   → bpm_start、bpm_trend、R²、RMSE
              └────────┬────────┘
                       ▼
                  R² ≥ 阈值 ?
                  ┌────┴────┐
                是│         │否
                  ▼         ▼
             输出该段落   ┌──────────────────┐
                         │ 4. 按间隔聚类标签 │ 找标签变化点切段
                         │    把序列切开      │ 每个子段
                         └────────┬─────────┘  递归回步骤 2
                                  ▼
                            递归直到每段都够稳
```

## 4. 第一步：拍间隔与"层级混叠"

设节拍时间戳为 `t(0), t(1), …, t(N-1)`（秒），拍间隔

```
Δt(i) = t(i+1) - t(i)
```

对匀速的歌，所有 `Δt` 应当几乎相等，取倒数就是 BPM。但实际检测结果里，`Δt` 会**忽长忽短**，
典型原因是**节拍层级判定错误**：

```
真实拍点:   ●   ●   ●   ●   ●   ●   ●   ●     (每拍 0.5s → 120 BPM)
检测结果:   ●       ●   ●       ●   ●   ●       (漏检/合并)
Δt:         1.0     0.5 1.0     0.5 0.5 ...
            ↑两拍并一拍   ↑正常    ↑正常

另一种情况：
检测结果:   ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ●     (把一拍拆成两拍)
Δt:         0.25 ...                            ↑倍速
```

如果直接对这些 `Δt` 求平均，得到的是**错误的 BPM**（比如把 120 算成 90）。
所以必须先判断"每个间隔到底是几拍"。

---

## 5. 第二步：聚类归一化

### 5.1 做法

**① 对 `Δt` 做一维 k-means（k=2）**，得到两个簇中心 `c0 < c1`。

理由：混叠通常只涉及两个层级——"正常拍"和"两拍合一拍"。两簇就能覆盖绝大多数情况。
（老版本的可视化脚本里用过 k=3，应对更复杂的层级，本库留了 `kmeans_k` 参数。）

**② 每个间隔归到最接近的整数倍**：

```
ratio = c(label of Δtᵢ) / c0          // 相对最小簇的比值
multiplier = argmin over m∈{1,2,3,4} |ratio - m|
if |ratio - multiplier| > tolerance:  // 默认 0.5
    multiplier = 1                    // 差得太远，不敢缩放，保守处理
```

**③ 用倍数把序列"均匀化"**：

```
t'(0) = t(0)
t'(i) = t'(i-1) + Δt(i-1) / multiplier(i-1)
```

举例：`Δt = [1.0, 0.5, 1.0, 0.5]`，两簇中心为 0.5 和 1.0 → 倍数 `[2, 1, 2, 1]` →
归一化后 `[0.5, 0.5, 0.5, 0.5]` → 拍间隔均匀，周期 0.5s → 120 BPM。**正确。**

### 5.2 为什么必须放在回归之前

二次回归假设"拍间隔是平滑变化的"。如果序列里混着 1.0s 和 0.5s 的间隔，
拟合出来的曲线会被这些跳变彻底带偏，R² 也会很低（看起来像"节奏不稳定"，
其实是检测层级的问题）。**先归一化、再回归**是本算法的核心顺序。

### 5.3 注意：归一化会改变时间轴

归一化后的 `t'` 已经不是真实时间了（把两拍压缩成一拍了），
所以回归得到的 `a`、`b`、`c` 是**归一化域**里的系数。
段落起止时间仍然用**原始** `beats.front()/back()` 给出，不受影响。
这也意味着 `a`,`b`,`c` 只在"该段落自身的归一化域"里有意义——
**跨段落不能直接比较 `a`**，要比较请用 `bpm_start` 和 `bpm_trend`。

## 6. 第三步：二次回归

### 6.1 为什么是二次而不是线性

线性模型 `t(n) = p·n + t0` 只能表示**匀速**（每拍周期恒定）。
一旦歌曲渐快或渐慢，周期就在变，线性模型必然出现系统性残差，R² 上不去。

二次模型 `t(n) = a·n² + b·n + c` 允许**周期线性变化**，正好对应"每拍 BPM 等量增减"：

```
瞬时周期  p(n) = t(n+1) - t(n) = a(2n+1) + b
          p(0) = a + b                     ← 起始周期
每拍周期增量 p(n+1) - p(n) = 2a
```

于是

```
bpm_start = 60 / (a + b)
bpm_trend = -60 · 2a / (a+b)²        （BPM 每拍变化量，负号表示周期变长则 BPM 下降）
```

### 6.2 怎么解

最小二乘 + 正规方程。要最小化 `Σ(t'ᵢ - (a·nᵢ² + b·nᵢ + c))²`，
对 a、b、c 求偏导置零，得到 3×3 线性方程组：

```
[ N      Σn     Σn²  ] [c]   [ Σt'   ]
[ Σn     Σn²    Σn³  ] [b] = [ Σn·t' ]
[ Σn²    Σn³    Σn⁴  ] [a]   [ Σn²·t']
```

代码里用**列主元高斯消元**求解（`quadratic_regression()`）：
先选主元（避免除以接近 0 的数），消元后回代。
主元绝对值小于 `1e-12` 判定为奇异矩阵，返回失败（对应"这段数据拟合不出来"）。

> 为什么不用闭式解（克莱姆法则）：三个未知数的行列式展开容易在平方和量级很大时丢精度，
> 列主元消元是数值上更稳的做法。

### 6.3 拟合优度

```
SS_res = Σ (t'ᵢ - t̂'ᵢ)²        （残差平方和）
SS_tot = Σ (t'ᵢ - mean(t'))²   （总平方和）
R²     = 1 - SS_res / SS_tot   （越接近 1 越好）
RMSE   = sqrt(SS_res / N)      （残差标准差，单位秒）
```

R² 在**归一化域**上计算。R² ≈ 1.0 表示"这段的节拍可以非常精确地用一条二次曲线描述"，
即速度在等量地渐变。

## 7. 第四步：多 BPM 段检测（递归分裂）

这是"多 BPM 段"的核心。**思路：先用一个模型去拟合整段；拟合不好，说明这段内部速度不一致，
就把它切开，对每一半重新拟合；如此递归，直到每段都足够"像一条二次曲线"。**

### 7.1 完整算法（伪代码）

```
detect_dynamic_bpm(beats, opt, depth):
    # ---- ① 拟合整段 ----
    if len(beats) < opt.min_beats: return []          # 太短，放弃
    seg = estimate_segment_parameters(beats, opt)      # 聚类归一化 + 二次回归
    if 拟合失败: return []
    if seg.r2 < 0: return []                           # 比"用均值预测"还差 → 丢弃
    if seg.r2 < opt.min_r2_keep and 时长 < min_duration_keep: return []   # 低置信度且太短 → 丢弃

    # ---- ② 停止条件 ----
    if seg.r2 >= opt.r2_threshold: return [seg]        # 够稳了
    if len(beats) < 2 * opt.min_beats: return [seg]    # 再切就太小了
    if depth >= opt.max_depth: return [seg]            # 递归保护

    # ---- ③ 切分 ----
    intervals = diff(beats)
    labels = kmeans_1d(intervals, k=2)                 # 按间隔大小分成两类
    beat_labels = 把 labels 映射到每个拍上（n-1 个间隔 → n 个拍）
    segments = 按 beat_labels 的"标签变化点"切出的连续块，丢掉长度 < min_beats 的

    if len(segments) <= 1: return [seg]                # 切不动，整段就是结果

    # ---- ④ 递归 ----
    result = []
    for s in segments:
        result += detect_dynamic_bpm(s, opt, depth+1)
    return result
```

### 7.2 切分是怎么找到边界的（关键理解）

注意：k-means 是在**间隔数值**上做的，不是在时间位置上的变点检测。但效果等价于找边界，
原因是：

- **分段变速**（前慢后快）：慢的间隔集中在前面，快的集中在后面 →
  两个簇分别对应"前半"和"后半" → 标签序列形如 `00001111` → 变化点在中间 → 正好切开。
- **层级混叠**（某一段被检测成两拍合一拍）：那一段的间隔明显更大 →
  标签在这段首尾各变一次 → 切出来的正是混叠的那一段，单独归一化后就能正确拟合。
- **渐变**（BPM = BPM + 1）：间隔单调变化，标签序列是"一刀切"，
  切点落在数值中位数附近 → 相当于把速度区间**二分**；递归继续二分，直到每段的
  R² 达标。这正是为什么一首持续加速的歌会被切成十几个段落（见验证数据）。

一句话：**这个算法本质是对"速度区间"做递归二分，而不是对"时间轴"做变点检测。**
理解这一点，才能理解它的行为和它的局限（见第 12 节）。

### 7.3 标签如何映射到拍

间隔有 `N-1` 个，拍有 `N` 个，需要一一对应：

```
beat_labels[0]   = labels[0]        // 第 0 拍用第 0 个间隔的标签
beat_labels[i]   = labels[i-1]      // 中间拍用"前一个"间隔的标签
beat_labels[N-1] = labels[N-2]      // 最后一拍用最后一个间隔的标签
```

（原版实现对最后一个元素用了 `labels.back()`，语义相同。）

## 8. 置信度与剪枝

| 规则 | 条件 | 动作 | 目的 |
|---|---|---|---|
| 拟合失败 | 高斯消元判定奇异 / 起始周期 ≤ 0 / 聚类出现空簇 | 该段返回空 | 数据本身不可拟合 |
| 负相关 | `R² < 0` | 丢弃该段 | 二次模型比"直接取均值"还差，说明这段根本不是渐变节奏 |
| 低置信 + 短 | `R² < 0.9` 且时长 `< 5s` | 丢弃该段 | 短且乱的小碎片，多半是检测噪声（如间奏、鼓点空白） |
| 拍数不足 | `len < min_beats` | 丢弃/停止分裂 | 样本太少，拟合没有统计意义 |
| 递归深度 | `depth ≥ max_depth` | 停止分裂 | 防止病态数据无限递归 |

注意"低置信 + 短"是**与**条件：一段 5 秒以上、R²=0.8 的段落会被保留（可能是自由节奏的过门），
而 2 秒、R²=0.8 的碎片会被丢掉。

## 9. 关于 k-means 初始化的稳定性

### 9.1 问题的发现

原版 `CppDataAnalyzer.cpp` 的 k-means 用 `std::random_shuffle` 做**一次**随机初始化
（无参数版本内部用 `rand()`）。我们用同一份数据、只改变初始化种子，实测结果：

| 用例 | 不同种子下的结果 |
|---|---|
| Protocol（essentia 检测） | 8 个种子结果一致（113.985） |
| Protocol（madmom 检测） | **种子 1/3/7 直接失败**（空簇 → 整个分析返回"未检测到有效段落"） |
| BPM = BPM + 1 | 段落数在 **11 ~ 15** 之间跳，平均 BPM 在 **130.8 ~ 135.4** 之间波动 |

两个后果都很严重：

1. **结果不可复现**：同一首歌换个编译/换台机器可能得到不同的分段方案。
2. **退化数据直接失败**：madmom 的 DBN 跟踪把拍点量化到 10ms 栅格，
   大量间隔**完全相等**；此时两个初始中心可能取到同一个值（因为数据里就只有那么几个不同值），
   所有点都归到簇 0，簇 1 为空 → 判定失败。

### 9.2 Python 版为什么稳

Python 版用的是 `sklearn.cluster.KMeans(n_clusters=2, random_state=0, n_init=10)`：
`n_init=10` 表示**随机初始化 10 次，取簇内平方和(SSE)最小的那个解**。
这大幅降低了陷入坏解的概率。C++ 移植时只做了一次初始化，把这层鲁棒性丢了。

### 9.3 头文件版的解决办法

- **k = 2 时，直接用一维精确最优划分**：把数据排序，枚举所有切分点，
  用前缀和 O(1) 求每侧的簇内平方和，取总 SSE 最小者。

```
SSE(s) = [Σ_{i<s} xᵢ² - (Σ_{i<s} xᵢ)²/s] + [Σ_{i≥s} xᵢ² - (Σ_{i≥s} xᵢ)²/(n-s)]
```

  结果**完全确定、与种子无关**，等价于 `n_init → ∞`。
  另外它天然不会产生空簇（切分点保证两侧各至少一个点），顺手解决了退化数据的失败问题。

- **k > 2 时**：做 `n_init` 次 Lloyd 迭代（默认 10 次，对齐 sklearn），按 SSE 选最优，
  并跳过有空簇的解。

### 9.4 效果

| 测试用例 | 原版（单次随机初始化） | 头文件版（精确最优） | Python（sklearn n_init=10） |
|---|---|---|---|
| Protocol（madmom） | 1 段 / 113.998 | 1 段 / **113.996** | 1 段 / **113.996** |
| Protocol（essentia） | 1 段 / 113.998 | 1 段 / **113.985** | 1 段 / **113.985** |
| BPM = BPM + 1 | 14 段 / 138.025 | **15 段 / 134.524** | **15 段 / 134.524** |

- 8 个不同种子现在给出**完全相同**的结果。
- 与 Python（已被认可的参考实现）**逐段 BPM 最大差异 0.000000**。

> 这说明原版 C++ 与 Python 的差异并不是实现细节问题，而是**随机初始化的抽样差异**。
> 头文件版把两者对齐到了同一个（最优）解。

## 10. 参数说明与调参建议

| 参数 | 默认 | 作用 | 调参建议 |
|---|---|---|---|
| `r2_threshold` | 0.99999 | 拟合优度达标即停止分裂 | **最重要的参数**。调低（如 0.999）→ 段落更少更长、更"粗"；调高 → 段落更细碎。可视化调试时可以先用 0.999 看大致结构 |
| `min_beats` | 5 | 段落最小节拍数 | 提高（如 10）可抑制短碎片；但会漏掉真正的短过渡段 |
| `max_depth` | 32 | 递归深度上限 | 一般不用改，纯粹是防病态数据的保险 |
| `min_r2_keep` | 0.9 | 置信度下限（配合时长） | 定得越低越宽容 |
| `min_duration_keep` | 5.0 | 时长短于此值才参与上面的剪枝 | 与上一项配合：短于 5 秒且 R²<0.9 的段被丢弃 |
| `kmeans_k` | 2 | 聚类簇数 | 只在遇到"三级以上层级混叠"时才考虑 3 |
| `kmeans_max_iter` | 100 | Lloyd 迭代上限 | 仅 k>2 时生效 |
| `kmeans_n_init` | 10 | 重启次数 | 仅 k>2 时生效，对应 sklearn 的 n_init |
| `multiplier_tol` | 0.5 | 整数倍判定容忍度 | 调小 → 更保守（更少缩放）；调大 → 更激进 |
| `seed` | 0 | 仅 k>2 路径使用的随机种子 | k=2（默认）时**完全不影响结果** |

## 11. 复杂度分析

设段落内节拍数 `n`：

| 步骤 | 复杂度 | 说明 |
|---|---|---|
| 拍间隔 | O(n) | |
| 精确一维 2-means | O(n log n) | 排序 O(n log n) + 枚举切分 O(n) |
| 二次回归 | O(n) | 一次遍历求 7 个和 + 3×3 消元 |
| R²/RMSE | O(n) | |
| 一次完整拟合 | **O(n log n)** | |
| 切分（标签映射 + 切块） | O(n) | |
| 递归 | 最坏 O(n² log n)，典型 O(n log² n) | 切分不平衡时会退化为每次只切掉一个拍，但有 `max_depth` 兜底 |

实际规模：一首 5 分钟、120 BPM 的歌约 600 个拍，完整分析在毫秒级。
**性能瓶颈不在这里，而在上游的节拍检测**（Essentia multifeature 是秒级的）。

## 12. 边界情况与已知限制

1. **它是"速度区间二分"，不是"时间变点检测"**
   如果一首歌是"慢—快—慢"（回到同样的慢速），二分之后两个慢段会落在不同的枝上，
   得到的是两个独立段落，而不是"一个被快段打断的慢段"。对跑步场景来说这没有问题
   （我们关心的是此刻的速度），但不要指望它输出"段落 A 重复出现"这种结构信息。

2. **段落边界不保证落在"音乐意义上的段落"上**
   切点由间隔数值的中位数决定，和歌曲的段落结构（主歌/副歌）没有直接关系。
   想要音乐意义上的段落，需要另外做结构分析。

3. **渐变速度会被切得很碎**
   默认 `r2_threshold = 0.99999` 非常严格，持续加速的歌会被切成十几个段落（实测 15 段）。
   这是"精度优先"的取舍；如果只想要少数几个大段，把阈值调到 `0.999` 量级。

4. **不处理静音/间奏造成的空档**
   如果两拍之间有长达数十秒的空白，那段间隔会被当成"一个大倍数"，归一化后产生畸变。
   上游的 `CUT_START/CUT_END` 和检测器的输出质量决定了下限。

5. **要求输入节拍按时间升序**（`parse_beats_csv()` 会自动排序，
   但直接调 `analyze_beats()` 时请自行保证）。

6. **段落数不设上限**：极端参数（阈值接近 1、min_beats 很小）可能产生大量微段，
   调用方需要自己按 `beat_count` 或时长过滤。

7. **对检测器质量敏感**：整个方法是"在检测结果上做拟合"，
   如果上游漏检/误检严重（比如整首歌都错判成半速），归一化只能救回"层级混叠"这一种情况，
   全局性的速度错误救不回来。这也是为什么要用 madmom 和 Essentia **两个检测器交叉验证**。

## 14. 数学附录

### 14.1 二次模型与 BPM 的关系

```
t(n) = a n² + b n + c                                    （n = 段落内拍序号）
p(n) = t(n+1) - t(n) = a(n+1)² - a n² + b(n+1) - b n
     = a(2n + 1) + b                                      （瞬时周期，秒/拍）

p(0) = a + b
BPM(n) = 60 / p(n)
bpm_start = BPM(0) = 60 / (a + b)

周期每拍增量： p(n+1) - p(n) = 2a
BPM 每拍增量： dBPM/dn = -60 · p'(n) / p(n)² ≈ -60 · 2a / (a+b)²   （在 n=0 处线性化）
```

注意 `bpm_trend` 是**线性近似**：真实 BPM 随 n 的变化是双曲线式的，
在段落较长、加速度较大时，用 `bpm_start + bpm_trend · k` 外推会逐渐偏离。
要精确的"第 k 拍 BPM"，请直接用 `Paragraph::bpm_at(k)`（它按公式精确计算，不做线性化）。

### 14.2 正规方程组的推导

最小化 `S(a,b,c) = Σᵢ (t'ᵢ - a nᵢ² - b nᵢ - c)²`

```
∂S/∂c = -2 Σ (t'ᵢ - a nᵢ² - b nᵢ - c) = 0   →  a Σnᵢ² + b Σnᵢ + cN = Σt'ᵢ
∂S/∂b = -2 Σ nᵢ(t'ᵢ - a nᵢ² - b nᵢ - c) = 0 →  a Σnᵢ³ + b Σnᵢ² + c Σnᵢ = Σ nᵢt'ᵢ
∂S/∂a = -2 Σ nᵢ²(t'ᵢ - a nᵢ² - b nᵢ - c) = 0 → a Σnᵢ⁴ + b Σnᵢ³ + c Σnᵢ² = Σ nᵢ²t'ᵢ
```

写成矩阵就是第 6.2 节那个 3×3 方程组（代码里按未知数顺序 c, b, a 排列）。

### 14.3 一维最优二划分的 SSE 公式

对已排序的 `x₀ ≤ x₁ ≤ … ≤ x_{n-1}`，把前 `s` 个划为一簇、其余划为另一簇：

```
SSE(s) = [ Σ_{i<s} xᵢ² - (Σ_{i<s} xᵢ)² / s ] + [ Σ_{i≥s} xᵢ² - (Σ_{i≥s} xᵢ)² / (n-s) ]
```

两个方括号分别是两簇的簇内平方和（利用了 `Σ(x-μ)² = Σx² - (Σx)²/k`）。
用前缀和 `pre`、`pre2` 可以 O(1) 求出，枚举 `s = 1 … n-1` 取最小即得全局最优解。
