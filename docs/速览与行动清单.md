## 1. 五分钟看懂这个系统

### 1.1 一句话

**把音乐变速，让它的拍子踩在你的脚步上。**

你在跑，步频会变（上坡、累了、冲刺）。音乐实时加减速，让自己的鼓点一直落在你脚上。

### 1.2 核心只有一条规则

把**音乐的节拍**想成一个转盘上的指针——每来一拍转一圈；**你的脚步**是另一个转盘——每迈一步转一圈。

```
        音乐转盘                    脚步转盘
          ╭───╮                      ╭───╮
        ╱   ↑   ╲                  ╱   ↑   ╲
       │    │    │                │    │    │
        ╲   │   ╱                  ╲   │   ╱
          ╰───╯                      ╰───╯
       一拍转一圈                    一步转一圈
```

**两根指针的夹角 = 音乐和脚步错开了多少。**

于是整件事只剩两条规律：

| 规律 | 大白话 |
|---|---|
| **转速相同 → 夹角冻住** | 倍速 = 你的步频 ÷ 歌曲 BPM，夹角就永远不变。**这就是"对齐"的定义。** |
| **转速差 1% → 每步错开 0.02 → 8 秒后错开半个拍** | 所以精度要求很苛刻，必须一直微调 |

**⇒ 全部算法都在干同一件事：让两个转盘的转速一样，并盯着夹角。**

### 1.3 三种播放模式

| 模式 | 速度从哪来 | 谁跟着谁 | 难点 |
|---|---|---|---|
| **步频跟随** | 你**实测**的步频 | 音乐跟脚步 | 步频一直变，必须闭环追 |
| **恒定 BPM** | 规定一个数字（如 170） | 脚步跟音乐 | 起播时"夹角"无从得知 |
| **曲线** | 你画的曲线（热身 150 → 目标 170 → 放松） | 脚步跟音乐 | 同上 |

> 后两种是**开环**：算倍速用的步频 = 目标步频，所以**夹角一旦定下就永远不漂**，
> 根本不需要闭环控制。要解决的只有"最开始那一下夹角的对齐"。

## 4. 五条"不看会踩"的坑

### ① 脚步的歌曲位置必须"回填"，不能读"现在"

`StepEvent.timestamp` 是**波峰时刻**（= 落脚时刻），不是上报时刻。如果你在收到回调的瞬间去读 `getInputPosition()`，就等于把几十毫秒**抖动**加回去了 —— 而"完美"窗口只容得下 17~25 ms 抖动。

```cpp
// ❌ 错
double songSec = getInputPosition() / sampleRate;

// ✅ 对（用回填时间戳反查）
double songSec = songSecAt(e.timestamp, m);   // §11.1
```

> **现状（2026-09）**：这条已经实现 —— `step_pipeline.hpp` 里的 `SongClock` 用脚步的 `e.timestamp` 回查历史歌曲位置，不读“现在”。

### ② `stepDelaySec` 的单位是"歌曲秒"，不是"墙钟秒"

现有实现的换算是 `stepDelaySec × B / 30`，**缺了一个 m\* 倍**（最多差一倍）。写上层参数前先决定用哪个单位，建议**直接用 offset 单位**（界面上它就是"对齐微调"）。

### ③ `firstBeatSec` 为负：**取模，不要 clamp**

第一拍算出负数是**弱起，完全正常**。直接 clamp 到 0 会把**整个网格平移**（180 步/分下 = 0.72 个单位，比整个"好"窗口还大），症状是"听起来差了半拍"但代码每行都对。

```cpp
anchor = f - P * floor(f / P);   // ✅ 网格不变，且 ≥ 0
// anchor = max(0.0, f);         // ❌ 网格被平移了
```

### ④ 旧版 `LiveStretchPlayer.h` 不要用

判据：`stop()` 里带一句 `if (!running_) return;`。自然播放结束后 `running_ == false` 但线程仍 joinable，
这句守卫会让 `stop()` 永不 `join()`，随后重播或析构时直接 `std::terminate()`。
**工程里的这份已经删掉了那行 —— 一律以工程为准。**

（`stretchbridge.cpp` 工程里那份的帧计数还是 `int`，有更新版的话可以合一下；但它本来就不编进 App，优先级低。）

### ⑤ 同一时刻只允许一个"速度来源"

两首歌同时在响（接歌）时，必须由**同一个**倍速值驱动，否则网格立刻错开。
另外两个 `LiveStretchPlayer` **不能各自起线程排拍**（会相对漂移），要改成一个 Mixer 线程拉两个 engine。
