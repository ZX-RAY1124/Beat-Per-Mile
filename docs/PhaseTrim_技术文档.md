# PhaseTrim 技术文档（预设模式的相位同步工具）

> 源文件：`phase_trim.hpp`（纯头文件 · C++11 · 只依赖 `beatgrid.hpp` · 约 230 行）
> 当前位置：**`entry/src/main/cpp/phase_trim.hpp`（已入工程）**
> 设计背景见 `C++核心协同方案.md` §8.6；本文只讲"它是什么、怎么用、在哪用"。

---

## 1. 它干了什么（30 秒版）

**把实测的相位偏置折回 0，但不改变平均速度。**

音乐和脚步的节拍本来可能固定错开一点（计步延迟 + 耳机输出延迟造成的）。要把这个错位折回去，
但**不能直接跳**（改播放位置会有可听的内容跳跃），**也不能改平均速度**（那就变成另一种跟随模式了）。

做法：给倍速叠一个**有界、双向、临时**的偏差 δ

```
实际倍速 = 规定倍速 × (1 + δ)      δ 的取值范围是 [-deltaMax, +deltaMax]
```

相位会以 `2·δ·(C/60)` 个 offset 单位/秒 的速度被搬动，而 **δ 最后一定收回 0** ——
所以长期平均速度仍然严格等于规定倍速。

> **一句话**：它不是"变速工具"，是"把错位挪回去的工具"。

## 3. 三个核心概念

### 3.1 δ 是什么

它是叠在"规定倍速"上的一个**小偏差**，单位是倍速的百分比：

| `deltaMax` | 效果 |
|---|---|
| 0.02（默认） | 最多 ±2% 变速。**听感上基本不可辨** |
| 0.05 | ±5%，开始能听出速度在变 |
| 0 | 等于关掉（δ 永远为 0） |

**δ = 0 是常态**：对齐完成之后它就归零了，音乐严格按曲线/规定值播放。

### 3.2 ★ 方向约定（最容易搞反的地方）

```
r        : 实测相位偏置（offset 单位，圆量）
           r > 0 = 脚步相对拍点"偏晚" = 拍点来得太早
err      = 当前偏置 − 目标偏置，范围 (-1, 1]，正 = 当前偏晚

偏晚(err > 0)  ⇒  要让拍点【晚点来】  ⇒  【减慢】  ⇒  δ < 0
偏早(err < 0)  ⇒  要让拍点【早点来】  ⇒  【加快】  ⇒  δ > 0

所以：  目标 δ = −gain × err
```

配着漂移动力学看：`d(r)/dt = +2·δ·(C/60)`，代入 δ < 0 ⇒ r 减小 ⇒ 朝 0 收敛 ✓

**注意错误计算必须用圆周差**。`+0.9` 和 `-0.9` 直接相减是 1.8（差了两圈），
圆周差只有 0.2。所以：

```cpp
// ❌ 错
const double err = r - rTarget;
// ✅ 对
const double err = beatgrid::circularError(r, rTarget);
```

`PhaseTrim` 内部已经用了 `circularError()`，你只需要知道"不要在外面再减一遍"。

### 3.3 为什么 δ 最后必须回到 0

如果 δ 停在一个非 0 的值，音乐就会**永久**偏离规定倍速。所以规则是：

- **不介入时，目标 δ = 0**（δ 以 `slewPerSec` 的速率平滑收回）
- `enabled = false` 时也会**收回 0**，不是冻在原地

这两条保证了"**平均速度 = 规定速度**"这个前提不被破坏。

## 4. API 详解

### 4.1 参数（可直接写，`update()` 每次都会夹取到安全区间）

| 参数 | 默认 | 含义 |
|---|---|---|
| `rTarget` | 0.0 | 目标相位（offset 单位）。0 = 让拍点正中踩在脚步上 |
| `deltaMax` | 0.02 | `abs(δ)` 上限 = 最多 ±2% 变速 |
| `deadband` | 0.08 | 绝对误差小于它时把 δ 收回 0（避免常驻微调） |
| `gain` | 0.5 | 比例增益：目标 δ = `−gain × err` |
| `slewPerSec` | 0.01 | δ 每秒最多变化多少（防速度阶跃） |
| `guardOnly` | **false** | `false` = 伺服（默认，同步工具）；`true` = 护栏 |
| `guardAt` | 0.60 | 仅护栏模式：误差超过它才介入 |
| `guardExit` | 0.20 | 仅护栏模式：误差低于它才退出（迟滞） |
| `enabled` | true | 总开关 |

### 4.2 控制

```cpp
trim.reset();                    // 清空状态，δ 归零
trim.sanitize();                 // 参数自检（update 内部也会调）
trim.setTargetOffset(r);         // 设目标相位（会折叠到 [-1,1)）
trim.setNudge(nudge);            // 滑条：nudge ∈ [-50, +50] → rTarget ∈ [-0.5, +0.5]
```

### 4.3 推进（核心）

```cpp
double update(double r, double dt);   // 返回 (1 + δ)
```

- `r` ：实测相位偏置（offset 单位，圆量）—— 一般就是 `beat.offset(songSec)`
- `dt` ：距上次调用经过的**墙钟秒**
- 返回：应乘到"规定倍速"上的系数

```cpp
const double r      = beat.offset(songSec);      // 实测相位
const double factor = trim.update(r, dtWall);    // (1 + δ)
player.setSpeed(cTarget / songBPM * factor);     // 规定倍速 × 系数
```

> `dt <= 0` 或非有限时**只返回当前系数，不改任何状态**（没法积分）。

### 4.4 读数

| 函数 | 返回 |
|---|---|
| `factor()` | `1 + δ` |
| `delta()` | 当前 δ |
| `targetDelta()` | 本次算出的目标 δ |
| `engaged()` | 当前是否正在介入 |
| `errorOf(r)` | 圆周误差（诊断用） |
| `unitsPerSec(C)` | 当前相位搬运速率 = `2·δ·C/60` |
| `secondsToFix(err, C)` | 按当前速率把 err 拉到 0 大约几秒 |

## 5. 典型用法

### 5.1 预设模式下的持续同步（最主要的用法）

```cpp
bpmw::PhaseTrim trim;          // 默认就是伺服，不用改

// 控制周期（50 ms 或每个脚步）
const double songSec = player.getInputPosition() / sampleRate;
const double r       = beat.offset(songSec);
const double factor  = trim.update(r, wallNow - wallPrev);
const double m       = curve.cadenceAt(tSport) / bpmAt(songSec) * factor;
player.setSpeed(m);
```

### 5.2 起播 / 切歌后的一次性对齐

```cpp
// 收 8~12 个脚步的相位，算圆均值，然后让 PhaseTrim 把它拉回 0
const double r0 = circularMeanOffset(samples);
if (circularConcentration(samples) > 0.5 && std::fabs(r0) > 0.15) {
    trim.setTargetOffset(0.0);      // 目标就是 0（默认值，写出来更清楚）
}
// 之后正常 update，几秒内自动收敛
```

### 5.3 用户拖动「对齐微调」滑条

```cpp
// 滑条范围 [-50, +50]，单位 = 0.01 个 offset 单位
trim.setNudge(sliderValue);     // 拖到 0 = 精确对齐；拖开 = 用户偏好
```

### 5.4 ★ 切回动态模式时必须关掉

```cpp
void enterFollowMode() {
    trim.enabled = false;       // 相位交给 TempoFollower 的 CHASE
    // δ 会在一两秒内平滑收回 0，不会留下速度台阶
}
void enterPresetMode() {
    trim.enabled = true;        // 相位交回 PhaseTrim
}
```

### 5.5 错误示范

```cpp
// ❌ 动态模式下忘了关 PhaseTrim —— 两个控制器抢相位，会互相打架
followMode = true;
trim.enabled = true;

// ❌ 用护栏模式当对齐工具 —— 护栏对 0.6 以内的偏置【故意】不动
trim.guardOnly = true;
trim.setTargetOffset(0.0);      // 0.5 的偏置永远修不掉
```

## 6. 在哪使用

| 用在哪 | 用来干什么 | 对应任务 |
|---|---|---|
| **恒定 BPM 模式的速度来源** | 算完 `规定步频 / BPM` 后乘上 `factor()` | 任务 3 |
| **曲线模式的速度来源** | 同上（曲线插值出规定步频） | 任务 3 |
| **起播 / 切歌后的一次性对齐** | 观测几个脚步 → `setTargetOffset()` → 自动收敛 | 任务 2 / 4 |
| **「对齐微调」滑条** | `setNudge()` | 任务 2 |
| **模式切换** | 进动态模式前 `enabled = false` | 任务 1 |

**不在这里用**：动态模式（步频跟随）。那里相位归 `TempoFollower` 的 CHASE 管。

## 7. ★ 已知边界（别指望它做不到的事）

### 7.1 追不上"用户大幅偏离曲线"

预设模式的本分是**音乐是主、人跟着跑**。如果用户跑得比曲线快 9%：

```
相位漂移速率 = 2 × (1 − 用户步频/曲线步频) × (用户步频/60)
             = 2 × 0.081 × 3.08 ≈ 0.5 offset 单位/秒      → 扫一圈只要 4 秒

而 δ 的修正能力 = 2 × deltaMax × (C/60) = 2 × 0.02 × 3.08 ≈ 0.12 offset 单位/秒
```

**差 4 倍，两种模式都挡不住。** 想真正跟住用户，请切到动态模式（用 `TempoFollower`）。

### 7.2 护栏修不了小偏置

护栏的介入门槛是 `guardAt = 0.60`。所以 **0.5 的偏置它一动不动** —— 这是故意的
（护栏的职责是"别跑到反拍"，不是"精确对齐"）。**要当同步工具用，必须用默认的伺服模式。**

### 7.3 "不改变平均速度"的准确含义

指的是 **δ 最终会回到 0**，所以长期平均速度严格等于规定倍速。
但如果相位一直在漂（比如用户持续偏离曲线），δ 会**长期停在饱和值**上 ——
那段时间音乐就是偏离规定倍速的（最多 ±deltaMax）。这是"用 2% 的偏差换更近的相位"的取舍。

### 7.4 它不知道步频

`update(r, dt)` 不接收步频，所以**它对用户变步幅天然免疫**。
步频变了只影响"每单位 δ 能搬动多快"（正比于 C），不影响它收敛到哪。

自测结果（`-O2 -Wall -Wextra`，全绿）：

| 项目 | 结果 |
|---|---|
| C++ 自测（9 组） | **68 项全过** |
| 限幅 / 限速 | 4000 组随机参数 + 随机误差，δ 与变化率都没越界 |
| 方向约定 | 2000 组随机验证：err > 0 必得 δ < 0 |

| 护栏迟滞 | 进入 0.60 / 退出 0.20，正负方向都验过 |
| **闭环收敛**（走真实漂移动力学 `dr/dt = 2·δ·(C/60)`） | 见下表 |
| 垃圾输入 | NaN / inf / dt ≤ 0 / 参数写坏 全部不崩，且不改状态 |

**闭环仿真实测**：

| 场景 | 初始相位 | 收敛用时 | 最终相位 | 最终 δ |
|---|---|---|---|---|
| **伺服（默认）** / 180 spm | +0.50 | **4.34 s** | −0.040 | 0 |
| **伺服** / 180 spm | −0.50 | 4.34 s | +0.040 | 0 |
| **伺服** / 150 spm | +0.30 | 3.00 s | −0.020 | 0 |
| **伺服** / 170 spm | +0.80 | 7.18 s | −0.034 | 0 |
| 护栏 / 180 spm | +0.70 | 4.76 s | +0.081 | 0 |
| 护栏 / 180 spm | +0.50 | **不动** | +0.50 | 0 ← 设计如此 |
