### 图表的两种显示方式

| 模式 | 时间轴 | 能做什么 |
| --- | --- | --- |
| 普通 | 固定显示 **5 分钟**（`NORMAL_WINDOW_MINUTES`） | 左右拖动平移；拖点 |

## 2. 数据模型与三条不变量

```ts
/** 曲线上的一个编辑点 */
class EditPoint {
  /** 稳定 id：点按时间重新排序后靠它找回"当前编辑的是哪一个" */
  id: number;
  /** 时间（分钟） */
  time: number;
  /** 目标步频 */
  bpm: number;
}
```

页面状态里，**点的数组**和**时间总长度**是两个独立的 `@State`：

```ts
@State points: EditPoint[] = copyPoints(DEFAULT_POINTS);
@State totalMinutes: number = DEFAULT_TOTAL;
```

### 三条不变量（改代码时必须维持）

1. **第一个点的 `time` 恒为 0** —— 曲线的头
2. **最后一个点的 `time` 恒等于 `totalMinutes`** —— 曲线的尾
3. **至少 2 个点** —— 否则画不出线，所以首尾点不允许删除

前两条由这几处共同保证：

- `applyTotalMinutes()` 改总长度时，只把**最后一个点**挪到新终点，其余点时间不动
- `minTotalMinutes()` 把总长度的下限设成**倒数第二个点的时间**，否则最后一个点会被挤到前面去
- 首尾点的**时间滑条是锁住的**（`.enabled(false)`），图上拖它们时也只改 BPM

### 为什么以「时间」为锚点，而不是比例

早期版本存的是归一化比例（0~1），改总长度会把整条曲线**拉伸**。现在存绝对时间：

- 30 分钟改成 45 分钟：原来的 0/5/10/15/20/25 分钟**原样不动**，只有尾点从 30 挪到 45
- 这符合直觉 —— 用户调的是"第 10 分钟该跑多快"，改总时长不该把他已经调好的部分挪走

### id 与排序

`id` 用「当前最大 id + 1」，**不复用已删除的 id**，避免"删了又加"导致 id 撞车、"当前编辑点"找错人。

点在时间上跨界（比如把点3拖到点2左边）时，会 `sort` 按时间重排，然后**按 id 找回它现在排第几**，序号跟着这个点走 —— 用户手上编辑的始终是同一个点。

## 3. 控件用法

### 3.1 Canvas 绘图

坐标系换算只有两个函数，图和交互共用：

```ts
private pointToX(minute: number): number {
  const plotW: number = this.ctx.width - PAD_L - PAD_R;
  return PAD_L + (minute - this.curStartMinute()) / this.curViewMinutes() * plotW;
}
private bpmToY(bpm: number): number {
  const plotH: number = this.ctx.height - PAD_T - PAD_B;
  return PAD_T + (1 - (bpm - BPM_MIN) / (BPM_MAX - BPM_MIN)) * plotH;
}
```

要点：

- `ctx.width / ctx.height` 的单位是 **vp**；拿不到（≤0）就直接 return
- 画曲线前先 `save() + rect + clip()`，超出窗口的部分自动被切掉，不用自己算交点，画完 `restore()`
- 曲线下方用 `createLinearGradient` 做渐隐填充
- **坐标轴要标数值和单位**：纵轴 80~240 固定（`BPM_TICK_STEP = 40`），横轴刻度按窗口长度自动挑间隔（`niceTimeStep()`）；左上角标 `BPM`、右下角标 `min`
- Canvas 不会自动重绘：所有改数据的路径最后都要调一次 `drawChart()`；`onReady` 和 `onAreaChange` 里也要调
- ⚠️ **`ctx.font` 的字号单位是物理 px，不是 vp** —— 字号必须过一遍 `chartFont(vpSize)` 换算，否则字会小到看不清，详见 3.4 坑 3

### 3.2 手势：长按和拖动互斥

```ts
.gesture(
  GestureGroup(GestureMode.Exclusive,
    LongPressGesture({ repeat: false, duration: LONG_PRESS_MS })
      .onAction((event: GestureEvent) => { this.onChartLongPress(event); }),
    PanGesture({ direction: PanDirection.All })
      .onActionStart(...) / .onActionUpdate(...) / .onActionEnd(...) / .onActionCancel(...)
  )
)
```

`Exclusive` = 谁先满足谁生效，另一个作废：**按住不动**走长按，**一按就滑**走拖动。

按下位置从 `event.fingerList[0].localX / localY` 取（相对 Canvas 左上角），用来做命中判定。

### 3.3 两个复用组件

| 组件 | 用途 | 组成 |
| --- | --- | --- |
| `StepperRow` | 时间总长度 / 当前编辑点 | 标签 + [－] 输入框 [＋] + 可选后缀 |
| `SliderRow` | 点的时间 / BPM | 标签在上、滑条在下，右侧输入框（无加减） |

**为什么是 `@Component` 而不是 `@Builder`**：`@Builder` 多参数是**按值传递**，输入框的文本不会随状态刷新。要传会变的值就得用带 `@Prop` 的组件。

### 3.4 ⚠️ 四个踩过的坑

**坑 1：成员名不能叫 `enabled`**

`CustomComponent → BaseCustomComponent → CommonAttribute → CommonMethod`，而 `enabled` 是 `CommonMethod` 上的通用属性方法。成员同名会报：

```
Property 'enabled' in type 'SliderRow' is not assignable to the same property in base type 'CustomComponent'.
Type 'boolean' is not assignable to type '(value: boolean) => CommonAttribute'
```

所以组件里那个开关叫 `fieldEnabled`。**容易踩的其他名字**：`id / key / size / direction / align / clip / scale / rotate / translate / opacity / visibility / position / margin / padding / border / width / height / zIndex / gesture`。

**坑 2：输入框要"文本和数值分开"**

如果 `onChange` 里把夹紧后的值写回 `text`，用户想输「45」、输到「4」就会被夹成最小值。所以：

- `onChange`：文本原样保留，只把**能解析出来的数字**同步进数值状态
- `onEditChange(isEditing)`：编辑结束时才把文本规范回去（`this.totalText = this.totalMinutes.toString()`）

对应到方法命名：`applyTotalMinutes`（只改数值，不碰文本）vs `setTotalMinutes`（加减按钮用，两个都改）。

**坑 3：canvas 的 `font` 单位是物理 px，而画布坐标是 vp**

现象：`ctx.font = '13px sans-serif'` 画出来的刻度数字小到看不清 —— 整个「240」的宽度只有正文单个汉字的一半，看着像"字号设置压根没生效"。

根因：`CanvasRenderingContext2D` 的**画布坐标系是 vp**（`new CanvasRenderingContext2D(settings)` 用的默认单位），但 **font 字符串里的 `px` 是物理像素**，两者差一个屏幕密度（手机上约 3 倍）。所以 13px 实际只画出 4vp 出头的字，比 SDK 默认的 `normal normal 14px sans-serif` 还小一大截。

我第一次修的时候只是把 11 调到 13，肉眼看不出任何变化 —— 因为**单位本身是错的**，在错误的量级上做微调没有意义。

正确做法：**字号按 vp 定义，绘制时统一换算**：

```ts
/** vp 字号 → canvas 的 font 字符串（按屏幕密度换算成物理 px） */
function chartFont(vpSize: number): string {
  return Math.round(vp2px(vpSize)).toString() + 'px sans-serif';
}

const TICK_FONT_VP: number = 13;          // 横纵轴刻度数字
const UNIT_FONT_VP: number = 12;          // 轴单位 BPM / min
const POINT_FONT_VP: number = 12;         // 数据点序号
const POINT_FONT_CURRENT_VP: number = 14; // 当前编辑点的序号
```

`vp2px()` 是 ArkUI 的全局函数（和 `px2vp()` 一对），`Math.round` 是防止浮点尾巴进到字体字符串里。

**连带影响**：字号"变大"到真实 vp 尺寸后，绘图区四周的留白也必须跟着放大，否则刻度会跑出画布、或者和坐标轴撞在一起：

| 留白 | 值 | 要放下的东西 |
| --- | --- | --- |
| `PAD_L` | 50 | 右对齐的「240」（13vp 约 21vp 宽）+ 8vp 间隙 |
| `PAD_T` | 34 | 纵轴单位「BPM」，且和最上面那条刻度（240）保持约 7vp 间隙 |
| `PAD_B` | 42 | 刻度数字（从 +6 起，13vp 高）+「min」（从 +21 起，12vp 高） |
| `PAD_R` | 18 | 末尾刻度（比如「45」）超出绘图区右边界的那一半 |

顺带一提：**「BPM」单位不能贴着最上面的刻度画**。它和「240」都是右对齐到同一个 x，字号放大后必然叠在一起，所以挪到了画布最上沿（`y = 8`）。

**这类问题的排查思路**：拿渲染出来的尺寸和已知大小的东西比一比（"只有正文单个字的一半宽"），算一下比例是不是刚好等于屏幕密度 —— 是的话就是**单位问题**，不是字号大小问题，调数值没用。

**坑 4：`Button` 写死宽度会把文案截成省略号**

保存按钮一开始写成 `.width(58)`，结果「保存」两个字显示成了「…」。

原因：**`Button` 自带左右内边距**（约 16vp × 2），写死 58 的话真正给文案的只有 26vp，而「保存」在 15fp 下约 30vp —— 塞不下就省略。

正确做法：**别写宽度**，只给内边距，让按钮按内容自适应：

```ts
Button('保存')
  .type(ButtonType.Normal)          //默认是 Capsule 胶囊形，这时 borderRadius 会被忽略
  .height(38)
  .padding({ left: 16, right: 16 }) //宽度 = 文案 + 内边距
```

两个连带的知识点：

- `.type(ButtonType.Normal)` 不能省。默认的胶囊形下 `borderRadius` 不生效，按钮会是圆头长条，和旁边的圆角输入框对不齐
- 同类风险：任何"定宽 + 有内边距 + 文字可能变长"的组合（后面如果做多语言，中文 2 字变英文 save 就更明显）

## 4. 图上四组操作

| 操作 | 触发 | 行为 |
| --- | --- | --- |
| 拖点 | 按在点上滑动（命中半径 `HIT_RADIUS = 22`vp） | 上下改 BPM、左右改时间；首尾点只让改 BPM |
| 拖时间轴 | 按在空白处滑动 | 平移时间轴（仅普通模式） |
| 长按点 | 按住不动 `LONG_PRESS_MS = 500`ms | 删除该点（`showAlertDialog` 确认）；首尾点弹 toast 拒绝 |
| 长按空白处 | 同上 | 在该位置加一个点（不确认），加完自动选中 |

拖点的位移是用**按下时记录的起始值 + 手指位移**换算的（不是累加）：

```ts
const dMinute: number = event.offsetX / plotW * this.curViewMinutes();
const dBpm: number = -event.offsetY / plotH * (BPM_MAX - BPM_MIN);
this.updatePointById(this.dragPointId, this.dragStartMinute + dMinute,
  this.dragStartBpm + dBpm, this.dragLockTime);
```

这样中途因为重排导致序号变化，手感也不会飘。

所有改点的路径（时间滑条 / BPM 滑条 / 图上拖点 / 加点 / 删点）最后都收敛到一个方法：

```ts
private updatePointById(id: number, minute: number, bpm: number, lockTime: boolean): void
```

`lockTime = true` 表示保持这个点原来的时间位置、只改 BPM。**新加改点的功能时请走这个方法**，不要在别处直接改 `this.points`。

## 5. 存取：曲线怎么读进来、又怎么写回去

### 5.1 入参：列表把序号传过来

从曲线列表的齿轮图标进来时，`pushPathByName` 带了 `{ index }`：

```ts
// CurveList.ets
const param: CurveEditParam = { index: index };
this.navPathStack.pushPathByName('CurveEdit_Page', param, true);
```

编辑器在 `onReady` 里读它，然后按序号从磁盘读整条曲线：

```ts
.onReady((context: NavDestinationContext) => {
  this.navPathStack = context.pathStack;
  const param: CurveEditParam = context.pathInfo.param as CurveEditParam;
  if (param !== undefined && param !== null) {
    this.loadCurve(param.index);   // 见 5.2
  }
})
```

没有参数（主页「页面导航」→ 曲线编辑）就保持默认曲线，保存时变成**新建**一条。

### 5.2 存储：一条曲线一个 json

数据结构和读写都在 `entry/src/main/ets/ets_libs/CurveStore.ets`，曲线列表、曲线编辑、标签编辑三个页面共用：

```
<filesDir>/Curve/1.json      第 1 条曲线（文件名 = 列表里的序号）
<filesDir>/Curve/2.json      第 2 条
```

```json
{
  "name": "曲线1",
  "points": [ { "time": 0, "bpm": 120, "type": "linear" } ],
  "tags":   [ { "time": 300, "text": "还剩 20 分钟坚持住" } ]
}
```

- ⚠️ **文件里的 `time` 是秒，界面上是分钟**。转换只走 `secToMin()` / `minToSec()`，别在别处手写 `/60`
- `loadCurve(index)` 读第 index 条 → `applyCurveFile()` 把点装进编辑器状态；**标签本页不编辑**，所以原样存进 `savedTags`，保存时再原样写回去
- `buildCurveFile()` 用编辑器里的点重新生成 `points`，`tags` 直接带 `savedTags`。曲线和标签在同一个 json 里，**谁保存都得把对方那部分带上**，否则就被抹掉了
- 删除用 `deleteAt()`，它会把后面的文件依次改名上前一位，维持"文件名连续"这个约定
- json 里**没有循环（isLoop）字段**，所以循环开关只存在于本次编辑，存不进文件

### 5.3 保存与退出

| 入口 | 行为 |
| --- | --- |
| 命名栏右侧的「保存」按钮 | 弹窗确认 → 写盘 + 提示"已保存"，**留在本页** |
| 返回时（`onBackPressed` 拦截） | 弹窗「保存 / 丢弃」；保存 = 先写盘再 pop，丢弃 = 直接 pop；点弹窗外面 = 留在本页 |

`saveCurveFile()` 的两条路：

- `curveIndex >= 0` → `saveAt(ctx, curveIndex, file)`，覆盖那一条
- 否则 → `appendCurve(ctx, file)` 新建，并把新序号记回 `curveIndex`，同一次会话里再保存就是覆盖而不是又建一条

### 5.4 ⚠️ 列表是怎么知道要刷新的（踩过的坑）

**不要用 `pushPathByName` 的 `onPop` 回调去刷新列表。** 实测在标签编辑页返回时那个回调**不触发**，结果就是：编辑页里保存成功了、json 也写对了，列表上的缩略图却一直是旧的。

现在的做法是「谁写盘谁通知」：

```ts
// CurveStore.ets —— saveAt / appendCurve / deleteAt 写成功之后
export function bumpRevision(): void {
  const n: number | undefined = AppStorage.get<number>(CURVE_REVISION_KEY);
  AppStorage.setOrCreate<number>(CURVE_REVISION_KEY, (n === undefined ? 0 : n) + 1);
}
```

```ts
// CurveList.ets —— 监听这个版本号
@StorageLink('curveStoreRevision') @Watch('onStoreChanged') storeRevision: number = 0;
```

写盘 → 版本号 +1 → 列表 `@Watch` 到就重读磁盘。跟用户怎么退出编辑页、`onPop` 有没有触发都无关。两个连带结论：

- 列表页在编辑页下面是**活着**的，所以编辑页里一按保存，背后的列表就已经重读完了，退回来直接是新的
- 卡片上的 `points / pointX / tagX` 是普通成员，只重读数据不会更新已有卡片，所以 `ForEach` 的键里带了 `listRevision`，让卡片整体重建

### 5.5 还没接的部分

把编辑好的曲线**下发给原生引擎**还没做，现在的出口只有磁盘。

## 6. 如果要原生来算这条曲线

编辑器本身不碰原生。如果以后曲线要由 C++ 生成/校验（比如按 `CppDataAnalyzer` 的段落结果拼一条初值曲线），**建议不要在这个页面里直接调 NAPI**，而是：

1. 进页面之前把数据准备好（调用方读原生接口，转成产物再传参）
2. 或者在这里加一个"生成初值"按钮，点了之后调原生拿结果、装进状态

这样页面只管编辑，数据来源和计算都在外面，两边都好测。

## 7. 待办与已知限制

| 项 | 说明 |
| --- | --- |
| **循环开关没持久化** | json 里没有 `isLoop` 字段（见 5.2），要存得先给格式加字段 |
| **没下发给原生引擎** | 保存只到磁盘，引擎还拿不到曲线（见 5.5） |
| **标题栏返回箭头绕过 `onBackPressed`** | 标签编辑页实测确实绕过（那边加了 `aboutToDisappear` 兜底保存）。本页没有兜底，所以**用标题栏箭头退出时不会弹「保存/丢弃」，改动会丢**；要么退出前按一下「保存」，要么给本页也补同样的兜底 |
| HDS 标题栏挂不了自定义按钮 | `HdsNavigationMenuContentOptions` 只支持图标项（`value` / `maxCount`），自定义 builder 在另一个接口 `BuilderOptions` 上，菜单用不了 —— 所以保存按钮放在命名栏右侧 |
| 没有撤销 | 删点/拖点不可撤销；要做的话可以维护一个操作栈 |
| 长按阈值固定 500ms | `LONG_PRESS_MS`，长按和拖动共用画布，按久了才滑会触发长按 |
| 颜色写死 | 图表配色是一组常量，暗色模式还没做 |
| 图表曲线颜色不跟随曲线 | 固定 `CHART_LINE`，要跟随就把 `this.lineColor` 接进 `drawChart` |
| 点数无上限 | 长按能一直加点，理论上会很密；需要的话加个上限提示 |
