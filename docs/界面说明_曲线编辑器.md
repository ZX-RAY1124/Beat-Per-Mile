## 2. 数据模型与三条不变量

```ts
/** 曲线上的一个编辑点 */
class EditPoint {
  /** 稳定 id：点按时间重新排序后靠它找回"当前编辑的是哪一个" */
  id: number;
  /** 时间（分钟） */
  time: number;
  /** 目标步频 */
  bpm: number;
}
```

页面状态里，**点的数组**和**时间总长度**是两个独立的 `@State`：

```ts
@State points: EditPoint[] = copyPoints(DEFAULT_POINTS);
@State totalMinutes: number = DEFAULT_TOTAL;
```

### 三条不变量（改代码时必须维持）

1. **第一个点的 `time` 恒为 0** —— 曲线的头
2. **最后一个点的 `time` 恒等于 `totalMinutes`** —— 曲线的尾
3. **至少 2 个点** —— 否则画不出线，所以首尾点不允许删除

前两条由这几处共同保证：

- `applyTotalMinutes()` 改总长度时，只把**最后一个点**挪到新终点，其余点时间不动
- `minTotalMinutes()` 把总长度的下限设成**倒数第二个点的时间**，否则最后一个点会被挤到前面去
- 首尾点的**时间滑条是锁住的**（`.enabled(false)`），图上拖它们时也只改 BPM

### 为什么以「时间」为锚点，而不是比例

早期版本存的是归一化比例（0~1），改总长度会把整条曲线**拉伸**。现在存绝对时间：

- 30 分钟改成 45 分钟：原来的 0/5/10/15/20/25 分钟**原样不动**，只有尾点从 30 挪到 45
- 这符合直觉 —— 用户调的是"第 10 分钟该跑多快"，改总时长不该把他已经调好的部分挪走

### id 与排序

`id` 用「当前最大 id + 1」，**不复用已删除的 id**，避免"删了又加"导致 id 撞车、"当前编辑点"找错人。

点在时间上跨界（比如把点3拖到点2左边）时，会 `sort` 按时间重排，然后**按 id 找回它现在排第几**，序号跟着这个点走 —— 用户手上编辑的始终是同一个点。

## 3. 控件用法

### 3.1 Canvas 绘图

坐标系换算只有两个函数，图和交互共用：

```ts
private pointToX(minute: number): number {
  const plotW: number = this.ctx.width - PAD_L - PAD_R;
  return PAD_L + (minute - this.curStartMinute()) / this.curViewMinutes() * plotW;
}
private bpmToY(bpm: number): number {
  const plotH: number = this.ctx.height - PAD_T - PAD_B;
  return PAD_T + (1 - (bpm - BPM_MIN) / (BPM_MAX - BPM_MIN)) * plotH;
}
```

要点：

- `ctx.width / ctx.height` 的单位是 **vp**；拿不到（≤0）就直接 return
- 画曲线前先 `save() + rect + clip()`，超出窗口的部分自动被切掉，不用自己算交点，画完 `restore()`
- 曲线下方用 `createLinearGradient` 做渐隐填充
- **坐标轴要标数值和单位**：纵轴 80~240 固定（`BPM_TICK_STEP = 40`），横轴刻度按窗口长度自动挑间隔（`niceTimeStep()`）；左上角标 `BPM`、右下角标 `min`
- Canvas 不会自动重绘：所有改数据的路径最后都要调一次 `drawChart()`；`onReady` 和 `onAreaChange` 里也要调

### 3.2 手势：长按和拖动互斥

```ts
.gesture(
  GestureGroup(GestureMode.Exclusive,
    LongPressGesture({ repeat: false, duration: LONG_PRESS_MS })
      .onAction((event: GestureEvent) => { this.onChartLongPress(event); }),
    PanGesture({ direction: PanDirection.All })
      .onActionStart(...) / .onActionUpdate(...) / .onActionEnd(...) / .onActionCancel(...)
  )
)
```

`Exclusive` = 谁先满足谁生效，另一个作废：**按住不动**走长按，**一按就滑**走拖动。

按下位置从 `event.fingerList[0].localX / localY` 取（相对 Canvas 左上角），用来做命中判定。

### 3.3 两个复用组件

| 组件 | 用途 | 组成 |
| --- | --- | --- |
| `StepperRow` | 时间总长度 / 当前编辑点 | 标签 + [－] 输入框 [＋] + 可选后缀 |
| `SliderRow` | 点的时间 / BPM | 标签在上、滑条在下，右侧输入框（无加减） |

**为什么是 `@Component` 而不是 `@Builder`**：`@Builder` 多参数是**按值传递**，输入框的文本不会随状态刷新。要传会变的值就得用带 `@Prop` 的组件。

### 3.4 ⚠️ 两个踩过的坑

**坑 1：成员名不能叫 `enabled`**

`CustomComponent → BaseCustomComponent → CommonAttribute → CommonMethod`，而 `enabled` 是 `CommonMethod` 上的通用属性方法。成员同名会报：

```
Property 'enabled' in type 'SliderRow' is not assignable to the same property in base type 'CustomComponent'.
Type 'boolean' is not assignable to type '(value: boolean) => CommonAttribute'
```

所以组件里那个开关叫 `fieldEnabled`。**容易踩的其他名字**：`id / key / size / direction / align / clip / scale / rotate / translate / opacity / visibility / position / margin / padding / border / width / height / zIndex / gesture`。

**坑 2：输入框要"文本和数值分开"**

如果 `onChange` 里把夹紧后的值写回 `text`，用户想输「45」、输到「4」就会被夹成最小值。所以：

- `onChange`：文本原样保留，只把**能解析出来的数字**同步进数值状态
- `onEditChange(isEditing)`：编辑结束时才把文本规范回去（`this.totalText = this.totalMinutes.toString()`）

对应到方法命名：`applyTotalMinutes`（只改数值，不碰文本）vs `setTotalMinutes`（加减按钮用，两个都改）。

## 4. 图上四组操作

| 操作 | 触发 | 行为 |
| --- | --- | --- |
| 拖点 | 按在点上滑动（命中半径 `HIT_RADIUS = 22`vp） | 上下改 BPM、左右改时间；首尾点只让改 BPM |
| 拖时间轴 | 按在空白处滑动 | 平移时间轴（仅普通模式） |
| 长按点 | 按住不动 `LONG_PRESS_MS = 500`ms | 删除该点（`showAlertDialog` 确认）；首尾点弹 toast 拒绝 |
| 长按空白处 | 同上 | 在该位置加一个点（不确认），加完自动选中 |

拖点的位移是用**按下时记录的起始值 + 手指位移**换算的（不是累加）：

```ts
const dMinute: number = event.offsetX / plotW * this.curViewMinutes();
const dBpm: number = -event.offsetY / plotH * (BPM_MAX - BPM_MIN);
this.updatePointById(this.dragPointId, this.dragStartMinute + dMinute,
  this.dragStartBpm + dBpm, this.dragLockTime);
```

这样中途因为重排导致序号变化，手感也不会飘。

所有改点的路径（时间滑条 / BPM 滑条 / 图上拖点 / 加点 / 删点）最后都收敛到一个方法：

```ts
private updatePointById(id: number, minute: number, bpm: number, lockTime: boolean): void
```

`lockTime = true` 表示保持这个点原来的时间位置、只改 BPM。**新加改点的功能时请走这个方法**，不要在别处直接改 `this.points`。

### 5.1 现状：页面没有任何外部入参

### 5.2 第一步：把曲线模型抽成公共文件

两边要传同一种数据，所以模型不能各自定义一份。新建 `entry/src/main/ets/ets_libs/CurveModel.ets`：

```ts
/** 曲线上的一个点（跨页面共用） */
export class CurvePoint {
  /** 稳定 id；新建时给个唯一值即可 */
  id: number = 0;
  /** 时间（分钟） */
  time: number = 0;
  /** 目标步频 */
  bpm: number = 150;

  constructor(id: number, time: number, bpm: number) {
    this.id = id;
    this.time = time;
    this.bpm = bpm;
  }
}

/** 一条曲线 */
export class CurveModel {
  /** 稳定 id：持久化时用它，不要用下标 */
  id: string = '';
  title: string = '';
  /** 折线颜色 */
  lineColor: string = '#FF6B6B';
  /** 时间总长度（分钟） */

  points: CurvePoint[] = [];
}
```

抽出来之后：

- `CurveEdit.ets` 把内部的 `EditPoint` 换成 import 进来的 `CurvePoint`（字段完全一样，改个名字和 import 即可）
- `CurveList.ets` 的 `CurveData` 换成 `CurveModel`

> ⚠️ 曲线列表现在的 `CurveData.points` 是 `number[]`（归一化的 0~1 折线 y 值），**它只够画预览图，没有 BPM 含义**，没法直接喂给编辑器。这正是要换成 `CurveModel` 的原因：一条曲线必须先有"时间 + BPM"的真实数据，预览图也要改成按真实的 BPM 绘制（把 `CurvePreview` 里的 y 映射从 0~1 换成按 80~240）。

### 5.4 第三步：编辑器读参数并落地

页面在 `onReady` 里能从 `NavDestinationContext.pathInfo.param` 拿到参数：

```ts
.onReady((context: NavDestinationContext) => {
  this.navPathStack = context.pathStack;
  this.loadFromParam(context);   // ← 新增
})
```

新增这个方法，做三件事：**读参数 → 校验不变量 → 落到状态里**：

```ts
/** 把外面传进来的曲线装进编辑器；没有传参就用默认曲线 */
private loadFromParam(context: NavDestinationContext): void {
  const param: CurveModel = context.pathInfo.param as CurveModel;
  if (param === undefined || param === null) {
    return; // 走 DEFAULT_POINTS / DEFAULT_TOTAL，也就是现在这个默认状态
  }

  this.curveId = param.id;
  this.curveTitle = param.title;
  this.lineColor = param.lineColor;
  this.totalMinutes = param.totalMinutes;
  this.totalText = param.totalMinutes.toString();

  // 传入的数据可能不满足不变量，这里统一修一遍（见下方 normalizePoints）
  this.points = normalizePoints(param.points, param.totalMinutes);

  this.currentNo = 1;
  this.currentText = '1';
  this.timeText = formatMinutes(this.currentTime());
  this.bpmText = this.currentBpm().toString();
  this.drawChart();   // onReady 时 Canvas 可能还没 ready，drawChart 里有 ≤0 的保护，无害
}
```

`normalizePoints` 是必须的 —— 外部数据可能是空数组、可能没排序、可能首尾不在 0 和总长度上：

```ts
/** 把任意来源的点整理成满足三条不变量的一串点 */
function normalizePoints(src: CurvePoint[], totalMinutes: number): CurvePoint[] {
  // 1) 深拷贝 + 时间夹进 [0, totalMinutes]
  const list: CurvePoint[] = [];
  for (let i = 0; i < src.length; i++) {
    let t: number = src[i].time;
    if (t < 0) { t = 0; }
    if (t > totalMinutes) { t = totalMinutes; }
    let b: number = Math.round(src[i].bpm);
    list.push(new CurvePoint(src[i].id, t, b));
  }

  // 2) 按时间排序（保证是单调的曲线）
  list.sort((a: CurvePoint, b: CurvePoint): number => a.time - b.time);

  // 3) id 去重（外部数据可能带重复 id）
  for (let i = 0; i < list.length; i++) {
    list[i].id = i;
  }

  // 4) 点数不足 2 个：补成"头尾两点"
  if (list.length === 0) {
    return [
      new CurvePoint(0, 0, DEFAULT_BPM),
      new CurvePoint(1, totalMinutes, DEFAULT_BPM)
    ];
  }
  if (list.length === 1) {
    return [
      new CurvePoint(0, 0, list[0].bpm),
      new CurvePoint(1, totalMinutes, list[0].bpm)
    ];
  }

  // 5) 首点强制 0、尾点强制 totalMinutes（不变量 1、2）
  list[0].time = 0;
  list[list.length - 1].time = totalMinutes;
  return list;
}
```

页面还要多两个状态来记住"我在编辑哪条曲线"：

```ts
@State curveId: string = '';
@State curveTitle: string = '';
@State lineColor: string = '#FF6B6B';   // 想让图表曲线跟着这条曲线的颜色走的话
```

（`lineColor` 可选 —— 现在图表的曲线颜色是写死的 `CHART_LINE`，要跟着曲线走就把 `drawChart` 里的 `CHART_LINE` 换成 `this.lineColor`。）

### 5.5 第四步：把编辑结果交回去

编辑器现在**没有"保存"动作**，所以必须补一个，否则 `onPop` 永远收不到结果。

**① 加一个"保存"按钮**（放操作台最下面一行最省事）：

```ts
Button('保存曲线')
  .width('100%')
  .height(44)
  .backgroundColor(CHART_LINE)
  .fontColor(Color.White)
  .borderRadius(12)
  .onClick(() => {
    this.saveAndBack();
  })
```

**② 保存 = 打包成 `CurveModel`，用 `pop` 丢回去**：

```ts
private saveAndBack(): void {
  const result: CurveModel = new CurveModel();
  result.id = this.curveId;
  result.title = this.curveTitle;
  result.lineColor = this.lineColor;
  result.totalMinutes = this.totalMinutes;
  result.points = this.points;      // CurvePoint[] 和 EditPoint[] 是同一个类

  this.navPathStack.pop(result, true);   // ← 触发调用方的 onPop
}
```

`NavPathStack` 的 `pop` 重载：`pop(result?: Object, animated?: boolean)`，结果会包在 `PopInfo.result` 里回到 5.3 那个回调。

**③ 调用方落地**（`CurveList.ets`）：

```ts
private applyEditedCurve(edited: CurveModel): void {
  const next: CurveModel[] = [];
  for (let i = 0; i < this.curves.length; i++) {
    const c: CurveModel = this.curves[i];
    if (c.id === edited.id) {
      next.push(edited);        // 换成新的
    } else {
      next.push(c);
    }
  }
  this.curves = next;           // V1：整体赋值才会刷新
  // 可选：顺手落盘，见 5.7
}
```

**④ 用户直接按返回键怎么办**

系统返回（侧滑 / 返回键）不会带 result，编辑就丢了。两个选择：

- 用 `HdsNavDestination` 的 `.onBackPressed()` 拦截，在里面自动保存一次再放行
- 或者接受"没点保存就丢弃"，但最好在页面标题或按钮上让用户看得出有未保存的改动

### 5.6 边界情况清单

| 情况 | 建议处理 |
| --- | --- |
| 曲线列表里的**「恒定BPM」**（没有点） | 要么禁止进编辑器（它是单值，应该有单独的输入页）；要么在 `openSettings` 里判类型，进编辑器时用 `normalizePoints([], total)` 生成一条直线 |
| 传进来的点是**空数组** | `normalizePoints` 补成头尾两点直线 |
| 只有 **1 个点** | 同上，用那个点的 BPM 拉一条直线 |
| 点的时间**超出总长度** | 夹到 `[0, totalMinutes]` |
| 点**没排序** | 按时间排序 |
| **id 重复或缺失** | 重排成 `0..n-1` |
| 总长度比倒数第二个点还小 | 不变量会破，所以 `normalizePoints` 里先保证排序，再用 `minTotalMinutes()` 兜底 |
| 编辑中途**删到只剩 2 个点** | 停住 —— 首尾点本来就禁止删除，不会少于 2 个 |

---

### 5.7 持久化（可选，但迟早要做）

跨页面传参只解决"这一次编辑"，应用重启后还是要从某处读回来。用 `@kit.ArkData` 的 preferences：

```ts
import { preferences } from '@kit.ArkData';

const STORE_NAME: string = 'beat_per_mile';
const KEY_CURVES: string = 'curves';

async function saveCurves(ctx: Context, curves: CurveModel[]): Promise<void> {
  const store: preferences.Preferences = await preferences.getPreferences(ctx, STORE_NAME);
  await store.put(KEY_CURVES, JSON.stringify(curves));
  await store.flush();
}
```

⚠️ **存稳定 id，不要存数组下标** —— 曲线被删掉或重排后，下标就全错位了。

## 6. 如果要原生来算这条曲线

编辑器本身不碰原生。如果以后曲线要由 C++ 生成/校验（比如按 `CppDataAnalyzer` 的段落结果拼一条初值曲线），**建议不要在这个页面里直接调 NAPI**，而是：

1. 进页面之前把数据准备好（调用方读原生接口，转成 `CurveModel` 再传参）
2. 或者在这里加一个"生成初值"按钮，点了之后调原生拿结果、走 `normalizePoints` 装进状态

这样页面只管编辑，数据来源和计算都在外面，两边都好测。

## 7. 待办与已知限制

| 项 | 说明 |
| --- | --- |
| **没有外部入参** | 见第 5 节，四步改造 |
| **没有保存动作** | 需要加"保存"按钮 + `pop(result)`，否则编辑结果只留在页面里 |
| 没有撤销 | 删点/拖点不可撤销；要做的话可以维护一个操作栈 |
| 长按阈值固定 500ms | `LONG_PRESS_MS`，长按和拖动共用画布，按久了才滑会触发长按 |
| 颜色写死 | 图表配色是一组常量，暗色模式还没做 |
| 图表曲线颜色不跟随曲线 | 固定 `CHART_LINE`，要跟随就把 `this.lineColor` 接进 `drawChart` |
| 点数无上限 | 长按能一直加点，理论上会很密；需要的话加个上限提示 |
