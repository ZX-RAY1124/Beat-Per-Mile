## 1. 三个页面的入口与路由

路由表在 `entry/src/main/resources/base/profile/router_map.json`（`CurveList_Page`、`SongList_Page`、`Playlist_Page`、`CurveEdit_Page`、`TagEdit_Page` 都注册了）。但要注意**注册了路由 ≠ 走路由**：

TabContent(){

}.tabBar(this.tabBarBuilder("sys.symbol.indent_right","曲线选择", 2))

- `SongList.ets` 仍是标准 NavDestination 页：`load()` 返回 `SongList()`（`SongList.ets:1086-1089`），由歌单列表页 push 进来并带参。

## 2. 新增一个页面要改的三处

1. **新建页面文件**，结构照抄现有页面（组件本体 + 一个 `load()` 构建函数）：

```ts
import { HdsNavDestination } from '@kit.UIDesignKit';

@Component
struct Xxx {
  build() {
    HdsNavDestination() {
      // 内容
    }
  }
}

@Builder
export function load() {
  Xxx()
}
```

> 要做成主页 Tab 而不是独立页：不需要 `load()`，直接在 `Main.ets` 里 `TabContent(){ Xxx(...) } ` 即可（CurveList / Playlist 就是这样）。

2. **注册路由** `router_map.json`（要独立跳转时）：

```json
{
  "name": "Xxx_Page",
  "pageSourceFile": "src/main/ets/pages/Xxx.ets",
  "buildFunction": "load"
}
```

`name` 要和 `pushPathByName('Xxx_Page', ...)` 的字符串完全一致，`buildFunction` 必须是页面文件里 `export` 出来的函数名。

3. **加导航入口**：独立页在 `Main.ets` 的 `PageMenu()` 里加 `MenuItem`（受控写法，每个 MenuItem 里要先 `isMenuShow = false` 再跳转）；Tab 页则在 `HdsTabs` 里加 `TabContent`。
   - ⚠️ `HdsTabs` 的直接子节点**必须全部是 `TabContent`**。`Main.ets:588-591` 记录了踩过的坑：组件夹在两个 TabContent 中间会被算成占位子节点，导致 Tab 索引整体后移。

## 3. 共用页面骨架与坑

```ts
@Component
struct Xxx {
  @State navPathStack: NavPathStack = new NavPathStack();

  build() {
    HdsNavDestination() {
      // 内容
    }
    .titleBar({ content: { title: { mainTitle: '标题', mainTitleSize: 20 } } })
    .onReady((context: NavDestinationContext) => {
      this.navPathStack = context.pathStack;   // 拿到导航栈，之后要跳别的页就用它
    })
  }
}
```

### 坑 1：HDS 的标题栏是「悬浮」在内容之上的，必须自己让位

不管它，列表第一项会和大标题重叠。让位要加在**滚动容器**上，不要加在内容上：

```ts
Scroll() { /* 或 List() */ }
  .padding({ top: $r('sys.float.single_line_titlebar_height') })
```

- 放在滚动容器上：内容永远在标题栏下方滚动；
- 只加在内容上：滚起来之后下面的内容还是会从标题栏底下穿过去。

用系统 token 而不是写死数值：手机是 56vp，平板/2in1 那套资源是 86vp，会自动适配。

### 坑 2：V1 下数组/对象必须「整体重新赋值」才会刷新

```ts
// 不会触发刷新
this.selectedIndexes.push(index);

// 正确：造一个新数组再赋值
const next: number[] = [];
// ...填充 next...
this.selectedIndexes = next;
```

三个页面全是这么写的：`toggle()` / `moveInPlaylist()` / `reloadCurves()` 都先建新数组再整体赋值（`SongList.ets:790-822`、`CurveList.ets:459-489`）。

### 坑 3：子组件传参约定

- **静态数据**（歌名、曲线点、颜色）用**普通成员**，父组件构建时传一次，之后不再更新；
- **需要跟着父组件刷新的**（选中状态）用 `@Prop`；
- **回调**用普通成员 + 箭头函数：`onToggle: () => void = () => {}`；
- ⚠️ **自定义组件上不能调 `.width()`、`.layoutWeight()` 这类通用属性**。尺寸要么写在子组件内部根节点上，要么在外面套一层容器（三个页面里都是套 `Column()` 再 `.layoutWeight(1)`）；
- ⚠️ 普通成员只在组件创建时初始化一次，父组件重建**不会**更新它。曲线列表的缩略图就吃过这个亏：`points/pointX/tagX` 是普通成员，必须让 `ForEach` 的键里带 `listRevision` 才能逼卡片重建（`CurveList.ets:424-432, 561-562`）。

## 4. 曲线列表页（CurveList.ets）

### 4.1 结构与入口

```
CurveList（主页「曲线选择」Tab）
├─ CurveCard：「恒定BPM」，points 为空 → 只有一行字 + 齿轮
│    └─ 齿轮弹自己的「设置默认BPM」输入框（CurveCard.show_BPM_setting）
└─ CurveCard × N（ForEach 渲染 CURVES，数据来自 <filesDir>/Curve/*.json）
     ├─ 标题（左上角）
     └─ Row
          ├─ CurvePreview（Canvas：网格 + 折线 + 标签竖线）
          └─ CardActions()  竖排图标
               ├─ gearshape  → 曲线编辑页（onSettings）
               ├─ bookmark   → 标签编辑页（onTags；sys.symbol.tag 不存在，所以用书签）
               └─ trash      → 删除这条曲线（onDelete，带确认弹窗）
```

选中态：整体往左上浮起（`offset(-6,-6)`）+ 阴影加重 + 四周描边（左侧更粗）。

选中哪条曲线会被写进 AppStorage：`select()` 里 `AppStorage.setOrCreate(ACTIVE_CURVE_KEY, index)`（`CurveList.ets:609-615`），0 = 恒定BPM。跑步播放器 / 正式播放器就读这个键去磁盘取曲线 —— **先选后用**。

### 4.2 数据来源与刷新

曲线不在内存里写死，而是**一条曲线一个 json** 存在本地：

```
<filesDir>/Curve/1.json     第 1 条曲线（文件名 = 列表里的序号）
<filesDir>/Curve/2.json     第 2 条
```

读写都在 `CurveStore.ets`，曲线列表 / 曲线编辑页 / 标签编辑页三个页面共用。`reloadCurves()` 每次从头读一遍磁盘，顺手把缩略图要的坐标算出来（`CurveList.ets:458-489`）：

- `pointX` / `tagX`：点、标签的归一化横向位置 —— ⚠️ 文件里的 `time` 是**秒**，总长度取最后一个点的时间（分钟），换算统一走 `secToMin()`，别在别处手写 `/60`；
- 缩略图上的青色竖线就是标签位置（`TAG_MARK_COLOR`），和标签编辑页保持一致。

**⚠️ 最大的坑：刷新不要建在 `pushPathByName` 的 `onPop` 回调上。** 实测在标签编辑页返回时那个回调**不触发**，表现就是「json 明明改了、缩略图不变」。现在的做法是「谁写盘谁通知」：

```ts
// CurveStore.ets：saveAt / appendCurve / deleteAt 写成功之后 bumpRevision()，版本号 +1
// CurveList.ets：监听它
@StorageLink('curveStoreRevision') @Watch('onStoreChanged') storeRevision: number = 0;
```

写盘 → 版本号 +1 → 列表 `@Watch` 到就重读磁盘，跟用户怎么退出编辑页、`onPop` 有没有触发都无关。另外卡片上的 `points / pointX / tagX` 是**普通成员**，光重读数据不会更新已有卡片，所以 `ForEach` 的键里带了 `listRevision`，让卡片整体重建。

> 同款机制在歌单列表页是 `@StorageLink('songListStoreRevision')`（`Playlist.ets:217-221`）。

### 4.3 新建 / 删除

- **新建**：主页「更多」→「新建曲目」→ `Curves_make_sure` 触发器通过 `@Link` 传进来，`onColumnAdd()`（`@Watch`）里调 `makeContent()`：`emptyCurve('曲线N', 30)` + `appendCurve()`，写成 `(n+1).json`（`CurveList.ets:414-420, 682-693`）。
  - ⚠️ 当前 `Main.menu_func()` 对 `Curves_make_sure` 连续取了两次反（`Main.ets:229-231`），净变化为 0，`@Watch` 不会触发 —— 也就是说「新建曲线」这条链现在是哑的。属于已知 bug，改的时候只需让它产生一次真实变化（或者新建入口直接调 `appendCurve`）。
- **删除**：垃圾桶 → `showAlertDialog` 确认 → `CurveStore.deleteAt(ctx, index)`（删文件并把后面的文件改名上前一位）→ 调整 `selectedIndex` → `reloadCurves()`（`CurveList.ets:641-679`）。

### 4.4 Canvas 画曲线预览

要点（`CurveList.ets:94-195`）：

- `RenderingContextSettings` / `CanvasRenderingContext2D` 每个组件实例一份，写在成员里；
- `onReady` 里开始画；`onAreaChange` 里再画一次（尺寸变化时重绘）；
- `ctx.width / ctx.height` 的单位是 **vp**；尺寸可能为 0，先判断再画；
- 折线四周留 6vp 内边距，否则线头会被裁掉一半；
- 横向位置优先用真实时间比例（`pointX`），没给就退化成等距（老数据）；
- 绘制顺序：面积 → 标签竖线 → 折线（折线画在最后，免得被竖线盖住）。

```ts
private settings: RenderingContextSettings = new RenderingContextSettings(true);
private ctx: CanvasRenderingContext2D = new CanvasRenderingContext2D(this.settings);

build() {
  Canvas(this.ctx)
    .width('100%')
    .height('100%')
    .onReady(() => { this.drawPreview(); })
    .onAreaChange(() => { this.drawPreview(); })
}
```

### 4.5 ⚠️ 选中态的描边**不能改宽度**

错误做法（会造成视觉 bug）：未选中 `borderWidth 0`、选中 `left: 6 / 其他: 1.5`。
因为 **ArkUI 的描边占据组件内部空间**，内容区宽度会从 `W` 变成 `W - 7.5`；而**布局变化是立刻生效的，动画只作用于描边的绘制**，结果就是选中瞬间曲线图右边缘「猛地往里缩一下」。

正确做法：**描边宽度恒定，只切换颜色**，同时用 padding 把描边占掉的宽度补回来：

```ts
.borderColor(this.selected ? this.accentColor : '#00000000')  // 未选中＝全透明，宽度仍然占位
.borderWidth({
  left: CARD_BORDER_LEFT,      // 6
  top: CARD_BORDER_OTHER,      // 1.5
  right: CARD_BORDER_OTHER,
  bottom: CARD_BORDER_OTHER
})
.padding({
  left: CARD_INSET_H - CARD_BORDER_LEFT,     // 16 - 6   = 10
  right: CARD_INSET_H - CARD_BORDER_OTHER,   // 16 - 1.5 = 14.5
  top: (this.points.length >= 2 ? CARD_INSET_V : CARD_INSET_V_TEXT) - CARD_BORDER_OTHER,
  bottom: (this.points.length >= 2 ? CARD_INSET_V : CARD_INSET_V_TEXT) - CARD_BORDER_OTHER
})
```

注意 **ArkUI 的八位色是 `#AARRGGBB`（alpha 在前）**，和 CSS 相反。阴影里的 `'#26000000'` 就是 15% 的黑。歌单列表页的卡片用的是同款写法（`Playlist.ets:56-65, 150-170`）。

### 4.6 选中动画

```ts
private select(index: number): void {
  this.getUIContext().animateTo({ duration: 220, curve: Curve.EaseOut }, () => {
    this.selectedIndex = index;
  });
  AppStorage.setOrCreate<number>(ACTIVE_CURVE_KEY, index);
}
```

一切会变的属性（offset / shadow / borderColor）都写在状态里，外面套 `animateTo` 改状态即可。

### 4.7 「恒定BPM」卡片的现状

恒定BPM 是列表第一项，只有一行字 + 一个齿轮。点齿轮弹 `show_BPM_setting()` 输入框（`CurveList.ets:274-331`）。**注意：现在点「确定」只把 `realBPM` 这个 `@State` 改了，没有任何落盘，也没写进播放器读的地方**（源码里就留了句「这里记得加上设置BPM的函数」，`CurveList.ets:290`）。要让它真正生效，得把值存进 CurveStore / AppStorage，并让播放器的恒速模式读它。

## 5. 歌曲列表页（SongList.ets）

### 5.1 定位与入口

SongList 现在是**曲库管理页**（音乐库 + 当前歌单的编辑面板），不是演示数据。它由歌单列表页 push 进来，并带一个 `SongListJSON` 参数：

```ts
// Playlist.ets:333-338
private EditSongListColumn(index: number): void {
  this.select(index);
  const param: SongListJSON = this.SL_JSON[index];
  this.navPathStack.pushPathByName('SongList_Page', param, true);
}
```

`onReady` 里读参数：`SONG_LIST_NAME / COLOR_PLAN / G_INDEX = param.index - 1`，然后 `reload_SongList()` 读曲库、`loadPlayList(param.songList)` 把歌单还原到面板（`SongList.ets:293-305`）。

### 5.2 真实数据源：两个 json

| 文件 | 内容 | 谁写 |
| --- | --- | --- |
| `<filesDir>/Media/Songs.json` | 曲库展示记录 `{songList: SongJSON[]}`，字段 `name/author/time/BPM/type`，外加稳定 id `filename`（音频文件名，含扩展名） | `add_music()`（`SongList.ets:826-872`） |
| `<filesDir>/Media/song_data.json` | CppDataAnalyzer 的详细多段 BPM `[{filename, filedir, segments:[{start,end,bpm}]}]` | `mergeSongData()`（`SongList.ets:1504-1566`） |

- 曲库读取：`reload_SongList()`（`SongList.ets:874-897`）—— 清空 `SONGS`，逐条塞进 `SongData`，`listVision += 1` 让 `ForEach` 键变化；
- **时长是真数据**：`meta.time`（native 回传的 `"3:42"`）存进 Songs.json，界面直接显示；`totalDurationText()` 用 `parseDuration` 累加后 `formatDuration` 还原（`SongList.ets:79-101, 769-783`）；
- ⚠️ **写 json 必须先 truncate**：`writeSync` 不截断，新内容短于旧内容时旧尾巴会残留，`JSON.parse` 直接抛（`SongList.ets:858-862, 1511-1513, 1556-1560`）；
- `song_data.json` 是「合并」而不是覆盖：同名 `filename` 替换，否则追加，避免冲掉协作者离线管线放进去的条目（`SongList.ets:1504-1554`）。

### 5.3 导入流程（pick 文件 → 拷贝 → 分析 → 落库）

```
点标题栏菜单「从本地导入歌曲」
  → runImportFlow()：
     importing = true（先上锁，返回键/侧滑都拦住）
     → importFromPicker()：AudioViewPicker 多选（maxSelectNumber = 50）
        → 逐个 copyUriToSandbox()：拷贝 + 字节级校验 → 成功返回沙箱路径
     → openImportDialog()：不可取消的进度弹窗
     → analyzeSequentially()：逐首串行
        → analyzeMusicAsync(path, cb)：native 分析，回调回传 SongMeta
        → add_music()：写 Songs.json（含 filename）
        → add_song_data()：analyzeSongSegments(path) + mergeSongData() 写 song_data.json
     → 重新 reload_SongList()
     finally → closeImportDialog(done)：关弹窗 + 解锁
```

关键实现点：

- **弹窗必须在 picker 返回之后再开**（`SongList.ets:589-599`）。提前开会和系统 picker 抢焦点，用户从头到尾看不到弹窗（实测返回键被拦了、但没弹窗）；
- 三道锁防止中途退出（`SongList.ets:576-587`）：`autoCancel = false`、`onBackPressed` 里判 `importing`、弹窗里没有取消按钮；
- `closeImportDialog()` `await` 打开时存下的 Promise（`openCustomDialog` 异步给 id），否则分析很快结束时 id 还没赋值，弹窗永远关不掉，人被困住（`SongList.ets:709-737`）；
- **逐首串行分析**：native 的分析进度是全局单例，并发会互相覆盖，`analyzeSequentially()` 用 `await new Promise` 串起来（`SongList.ets:1418-1461`）；
- 进度轮询：`startAnalyseProgress()` 每 500ms 读 `getAnalyseStatus()`，`phase/pct/elapsedMs` 打到日志并透传给弹窗（`SongList.ets:1099-1167`）。
- **⚠️ picker 导入的两个坑**（`SongList.ets:1169-1233`）：
  1. 不要用 `copyFileSync(fd, path)`：实测（HarmonyOS 6.0.2）传 picker URI fd 时既不抛异常也不拷贝，落盘 0 字节 —— 改用「手动分块 read/write」；
  2. **任何一次「只看一眼」的读都会移动 fd 游标**：早期版本拷贝前用同一个 fd 读了两次 16 字节「探测」，导致拷贝从第 32 字节开始、稳定丢头 32 字节（m4a 丢 ftyp box → FFmpeg 报 Invalid data）。所以探测 fd 必须即用即关，拷贝用全新 fd。

### 5.4 删除歌曲：四步缺一不可

左滑（`swipeAction.end`，`SongList.ets:244-252`）→ `confirmDelete` 二次确认 → `removeSong(filename, name)`：

1. `song_data.json` 里 filename 匹配的那条（`removeSongData`）；
2. `Media` 下的音频本体 + 同名 `<stem>_beats.csv`（`safeUnlink`，先 `accessSync` 判存在，不存在静默跳过）；
3. `Songs.json` 里的展示记录（`removeFromSongsJson`）；
4. **所有已保存歌单**里的副本（`PlayListStore.removeSongFromAllPlaylists`）。

匹配统一以 **filename 为稳定 id**，只有早期缺 filename 的数据才退回按 name。删除后还要把 `selectedIndexes` 里比它大的下标统一前移一位（`SongList.ets:1010-1037`）。

顺序是先删外部文件、最后删 Songs.json 主记录：中途失败时列表里那首歌还在，用户能重试；反过来会出现「列表没了、文件还占空间」的孤儿文件。

### 5.5 播放列表面板与保存

- 交互流：曲库点某行 → 加入/移出当前歌单（新加入的放最顶部，`toggle()`）→ 底部悬浮胶囊显示「已选 N 首 · 总时长」→ 点胶囊上拉半屏面板 → 面板里逐首移除 / 长按拖动排序（`SongList.ets:354-467, 789-822`）。
- 面板里的 `TextInput` 就是歌单名（`SONG_LIST_NAME`）；返回时的 `showBackDialog()` 会问「确认保存」，保存走 `save_playList_plan(selectedIndexes)` + `PlayListStore.saveAt(ctx, G_INDEX, result)`（`SongList.ets:500-573`）。
- ⚠️ **面板顺序 = 文件顺序 = 播放顺序**。`loadPlayList` 按文件原序还原，`save_playList_plan` 也按面板顺序原样落盘（`SongList.ets:469-521`）。源码注释记录了曾经的 bug：`loadPlayList` 借 `toggle()` 逐首加（新歌 `unshift` 到最前）会把顺序倒过来，配合保存时的 `plan.reverse()` 才「看起来自洽」，代价是正式播放器把歌单倒着播。**别把 `reverse()` 加回来。**

### 5.6 详情行切成三栏（防止作者名顶掉 BPM）

```ts
Row({ space: COLUMN_GAP }) {
  // 第一栏：作者——唯一可伸缩的，超长自己省略
  Text(this.artist)
    .layoutWeight(1).maxLines(1)
    .textOverflow({ overflow: TextOverflow.Ellipsis })
  // 第二栏：时长——固定宽、右对齐
  Text(durationText).width(DURATION_WIDTH).textAlign(TextAlign.End)
  // 第三栏：BPM——固定宽、右对齐
  Text(this.bpm + ' BPM').width(BPM_WIDTH).textAlign(TextAlign.End)
}
```

作者是唯一会伸缩的，所以再长也只截断自己；时长和 BPM 固定宽度右对齐，**各行竖着对齐成一列**，扫起来很快。

### 5.7 List 的用法

- **淡分割线**用 List 自带的 `.divider()`，不是自己画线（`SongList.ets:259-264`）：

```ts
.divider({
  strokeWidth: 1,
  color: DIVIDER_COLOR,          // '#F0F0F0'
  startMargin: ROW_PADDING_H,    // 与文字左对齐
  endMargin: ROW_PADDING_H
})
```

- **给悬浮胶囊留空间**用 `.contentEndOffset()`，不要用 padding：

```ts
.contentEndOffset(CAPSULE_RESERVE)   // 只影响可滚动范围，最后一首能滚到胶囊上方
```

用 padding 的话底部会留一条永远滚不到的死区。行是普通行（无圆角无阴影），音乐库那一侧**不是卡片**。

### 5.8 带动画的复选框：用 HarmonyOS Symbol

```ts
SymbolGlyph(this.selected
  ? $r('sys.symbol.checkmark_square_fill')   // 选中：实心方框 + 对勾
  : $r('sys.symbol.square'))                 // 未选：空心方框
  .fontSize(24)
  .fontColor([this.selected ? SELECT_ACCENT : ICON_IDLE])
  .symbolEffect(new ReplaceSymbolEffect(EffectScope.WHOLE), true)
```

- `symbolEffect` 的第二个参数传 **true 而不是 this.selected**：这样「加入」和「移出」两个方向都有动画；
- `EffectScope.WHOLE` 是整体替换；`EffectScope.LAYER` 只动单层；
- 想去 SDK 里确认某个符号名存在：`<SDK>/openharmony/ets/build-tools/ets-loader/sysResource.js`（编译器就是拿这张表校验 `$r('sys.symbol.xxx')` 的）。

### 5.9 悬浮胶囊 + 上拉面板

```ts
Stack({ alignContent: Alignment.Bottom }) {
  List() { /* 音乐库 */ }
  if (this.selectedIndexes.length > 0) {
    this.PlaylistCapsule()
  }
}
.bindSheet(this.isSheetShow, this.PlaylistSheet, {
  detents: [SheetSize.MEDIUM, SheetSize.LARGE],   // 半屏起，可以往上拉成全屏
  dragBar: true,
  showClose: false,                               // 用面板头部自己的「完成」
  onDisappear: () => {
    this.isSheetShow = false;                     // ⚠️ 必须同步，否则状态会错乱
  }
})
```

`onDisappear` 这行很关键：用户下拉或点遮罩关闭面板时，`isSheetShow` 不会自己变 false，不同步的话下次点胶囊会出现「第一次没反应、第二次才开」。同样的坑在主页的 `PageMenu`（`bindMenu`）里也遇到过，处理方式一样。

### 5.10 拖动排序：用系统的 `Repeat.onMove`

```ts
Repeat<number>(this.selectedIndexes)
  .each((ri: RepeatItem<number>) => {
    ListItem() { /* 一行 */ }
  })
  .key((songIndex: number) => 'playlist_' + songIndex.toString())
  .onMove((from: number, to: number) => {
    this.moveInPlaylist(from, to);
  })
```

- 走的是**系统拖拽**（自带浮起缩略图和触感反馈），**不要手搓**；
- `moveInPlaylist` 就是「摘出来再插进去」两次 `splice`；
- 用 `ForEach` 没有这个能力，**必须是 `Repeat`**；
- ⚠️ **长按阈值不可配置**：`DragInteractionOptions` 里没有 duration 字段，实测约 500ms。没按够时常按，手指拖动会去拖整个半屏面板，这是预期行为。

## 6. 歌单列表页（Playlist.ets）

主页「歌单列表」Tab 内嵌的页面，数据来自 `PlayListStore`，卡片样式与 CurveList 保持一致（选中浮起 + 恒宽描边 + 阴影）。

- **列出歌单**：`readSongList()` 调 `PlayListStore.loadAll()`，把每条 `SongListJSON` 转成 `PlaylistData`（标题、封面占位色、歌曲数、描边色）；`onDidBuild()` 首次读，`@StorageLink('songListStoreRevision')` `@Watch` 到写盘通知后重读（`Playlist.ets:217-229, 304-329`）。
- **选中**：`select(index)` 写 `ACTIVE_PLAYLIST_KEY`（`Playlist.ets:198-204`）。`readSongList()` 里还会做一次「把看起来选中落实成真的选中」：没有有效选中就落到第 0 个，没有歌单就写 -1（`Playlist.ets:312-328`）。正式播放器按这个键组装队列。
  - ⚠️ 落盘读回来的可能是字符串，要先 `Number(raw)` 归一化，否则卡片高亮和播放器都会失效（`Playlist.ets:318-321`）。
- **新建歌单**：主页「更多」→「新建歌单」→ `PlayList_make_sure` 通过 `@Link` 传进来，`MakePlayListItem()` 调 `makeNewSongList()`：造一个 `{name:'新建歌单', songList:[], colorPlan, index}`，`appendSongList()` 落盘后重读（`Playlist.ets:207-214, 283-294`）。同样受 `Main.menu_func` 双重取反的影响（见 4.3）。
- **编辑/删除**：设置图标 → `EditSongListColumn(index)`：先 `select(index)`，再 `pushPathByName('SongList_Page', param)` 进歌曲列表页编辑；垃圾桶 → 确认弹窗 → `deleteAt()`（`Playlist.ets:333-361`）。
- 空状态：「还没有保存的歌单呢 / 点击右上角"+"以新建歌单」。
- 封面是占位色块 + 音符符号（`sys.symbol.music_fill`），没有真封面。

## 7. 数据与存储

### 7.1 CurveStore.ets（曲线 / 标签）

```
<filesDir>/Curve/<index+1>.json
{ "name": "...", "points": [{ "time": 秒, "bpm": 120, "type": "linear" }],
  "tags": [{ "time": 秒, "text": "..." }] }
```

导出的关键符号：`CURVE_REVISION_KEY`、`ACTIVE_CURVE_KEY`、`bumpRevision()`、`secToMin()/minToSec()`、`curveDir()/ensureDir()/fileNameOf()`、`emptyCurve()/makeWithTags()`、`loadAll()/count()`、`saveAt()/appendCurve()/deleteAt()`、`pointsToPreview()`、`CurveEditParam`、`POINT_TYPE_LINEAR`（`CurveStore.ets`）。

- 文件名就是列表序号，删除必须靠 `deleteAt()` 把后面的文件依次改名上前一位；
- 曲线 / 标签在同一个 json 里，谁保存都得把对方那部分带上，否则会被抹掉；
- ⚠️ `time` 秒 ↔ 分钟只走 `secToMin()/minToSec()`；
- json 里**没有循环（isLoop）字段**，所以循环开关存不进文件。

### 7.2 PlayListStore.ets（歌单）

```
<filesDir>/SongList/<index+1>.json
{ "index": n, "name": "...", "colorPlan": 0,
  "songList": [{ "name", "author", "time", "BPM", "type", "filename?" }] }
```

导出的关键符号：`SONG_LIST_REVISION_KEY`、`ACTIVE_PLAYLIST_KEY`、`bumpRevision()`、`SongJSON/SongListJSON`、`loadAll()/count()`、`saveAt()/appendSongList()/deleteAt()`、`removeSongFromAllPlaylists()`（`PlayListStore.ets`）。

- `SongJSON.filename` 是删除时定位「音频本体 + `_beats.csv`」的稳定 id；旧数据可能为 `undefined`，用前判空；
- 歌单 json 里存的是各自 `songList` 的**副本**，删歌时必须调 `removeSongFromAllPlaylists()` 清理，否则残留指向已删文件；
- `ACTIVE_PLAYLIST_KEY` 在 `Main.aboutToAppear()` 里用 `PersistentStorage.persistProp()` 落盘，跨重启记住（`Main.ets:176-181`）。

## 8. 接后端 / 原生接口现状

### 8.1 `index.d.ts` 里与本组页面相关的接口

权威声明：`entry/src/main/cpp/types/libentry/index.d.ts`。

| 接口 | 签名 | 作用 |
| --- | --- | --- |
| `analyzeMusicAsync` | `(path, cb: (meta: SongMeta \| null, err?: string) => void) => void` | **异步**分析音频，同目录生成 `<同名>_beats.csv`；成功回传 `SongMeta{name,author,time,BPM}`，失败 `meta=null` |
| `analyzeSongSegments` | `(path: string) => string` | 读 `_beats.csv`，CppDataAnalyzer 多段 BPM 拟合，返回 `SongSegmentsMeta` JSON（同步、毫秒级，必须在 `analyzeMusicAsync` 成功之后调） |
| `getAnalyseStatus` | `() => string` | 轮询分析进度 `{phase,pct,elapsedMs,running,error}`，建议 300~500ms 一次 |
| `musicAnalyse` | `(path: string) => void` | ⚠️ 旧接口：同步、阻塞主线程、不回传结果，**仅保留兼容，勿在新代码用** |
| `music_play / music_prepare` | `(url, cb) => number` | 播放 / 只预解码建会话，返回会话 id |
| `music_start / music_pause / music_resume / music_cancel` | `(id) => void` | 对会话发信号 |
| `music_seek` | `(id, sec) => void` | 跳到歌曲 sec 秒 |
| `music_set_speed` | `(id, speed) => void` | 按会话设置倍速（全局：同时出声的流共用拍周期） |
| `music_set_volume` | `(id, volume, rampMs) => void` | 音量 + 斜坡（交叉淡化基础） |
| `changeSpeed` | `(speed) => void` | 旧的全局倍速（写 `dataClip->accelerate`） |
| `musicGetStatus` | `(id) => string` | 原生播放状态 JSON：`state/frames/rate/posSec/durSec/startLatencyMs/error` |
| `setStretchEngineMode / getStretchEngineStatus` | `(mode) => void` / `() => string` | 变速引擎选择与自检 |
| `stepPipelineStart / Stop / SetScenario / SetTargetBpm / SetChaseDelayWindow / Status` | — | 步频管线（模拟源）+ 状态 JSON |
| `stepSensorStart / Push / Stop` | — | 真实传感器源（被动喂样） |
| `test_audio / add / squire` | — | 早期连通性测试接口，正式功能别用 |

ArkTS 侧调用示例（当前 `SongList.ets:10`）：

```ts
import { analyzeMusicAsync, getAnalyseStatus, analyzeSongSegments, SongMeta } from 'libentry.so';
```

### 8.2 旧文档「5.3 建议新增的 NAPI 接口」的落地情况

当时建议的 `analyseSong` / `setTempoCurve` / `setPlaylist` / `setTempoCallback` 并没有按这套名字实现，而是**换了更细的接口组合**：

| 当时的建议 | 现在实际的形态 |
| --- | --- |
| `analyseSong(path) => SongAnalysis\|null` | `analyzeMusicAsync`（异步 + 回调回传 `SongMeta`）+ `analyzeSongSegments`（多段 BPM） |
| `setTempoCurve(points, smooth)` | 没有独立下发接口：曲线先落盘，播放器按 `ACTIVE_CURVE_KEY` 读盘、装进 ArkTS 的 `RunDemoEngine`；native 侧的曲线推进尚未接通 |
| `setPlaylist(paths)` | 歌单落盘 `SongList/<n>.json`，播放器按 `ACTIVE_PLAYLIST_KEY` 读盘、按 filename 组队列 |
| `setTempoCallback(cb)` | 改为轮询：`stepPipelineStatus()` / `musicGetStatus()` 返回 JSON，播放器 5Hz 拉取 |

### 8.3 界面上还缺的

| 界面需求 | 现在的状态 | 还缺什么 |
| --- | --- | --- |
| 音乐库显示 BPM / 时长 | 导入时由 `analyzeMusicAsync` 填好 | — |
| 曲线交给引擎 | 落盘 + `ACTIVE_CURVE_KEY`，播放器读盘用 | native 曲线推进 / 直接下发接口 |
| 播放列表交给引擎 | 落盘 + `ACTIVE_PLAYLIST_KEY`，播放器按 filename 组队列 | — |
| 播放界面画进度/步频 | 走 `musicGetStatus` / `stepPipelineStatus` 轮询 | `music_play` 的 progress 回调仍未启用 |
| 恒定BPM 的默认值 | 输入框只改内存状态 | 落盘 + 播放器读取 |

### 8.4 加一个 NAPI 接口的三步

1. `entry/src/main/cpp/napi_bridge_center.cpp` 里写静态函数：

```cpp
static napi_value Xxx(napi_env env, napi_callback_info info) {
    size_t argc = 1;
    napi_value args[1] = {nullptr};
    napi_get_cb_info(env, info, &argc, args, nullptr, nullptr);
    // 取参数（字符串用 napi_get_value_string_utf8）
    // ... 业务 ...
    // 要回传就 napi_create_xxx + return result，不需要回传就 return nullptr
}
```

2. 在 `desc[]` 里注册（用 ArkTS 侧要用的名字）：

```cpp
napi_property_descriptor desc[] = {
    // ...
    {"xxx", nullptr, Xxx, nullptr, nullptr, nullptr, napi_default, nullptr}
};
```

3. 在 `entry/src/main/cpp/types/libentry/index.d.ts` 里补类型声明 —— **漏了这一步 ArkTS 会报找不到模块/类型**。
