> 日期：2026-09-13（3.5 / 3.6 与第 6 节已按现状改写：曲线已经落盘，刷新走写盘通知而不是 onPop）
> 范围：本轮新增的两个界面（曲线列表、歌曲列表）的控件用法、关键代码，以及接入原生/后端的方式
> 面向：参与本项目的协作者（ArkTS 侧与 C++ 侧都需要看第 5 节）

## 0. 速览

| 页面 | 文件 | 路由名 | 入口 |
| --- | --- | --- | --- |
| 曲线列表 | `entry/src/main/ets/pages/CurveList.ets` | `CurveList_Page` | 主页右上角「页面导航」按钮的子菜单 |
| 歌曲列表（音乐库 + 播放列表） | `entry/src/main/ets/pages/SongList.ets` | `SongList_Page` | 同上 |

两个页面都用 **状态管理 V1**（`@Component` + `@State` + `@Prop`），和项目里现有的 `Main.ets`、`Animation_test.ets` 保持一致。
**不要在这两个文件里混用 V2 装饰器**（`@ComponentV2/@Local/@Param`），V1 和 V2 不能写在同一个 struct 里。

## 1. 新增一个页面要改的三处

1. **新建页面文件**，结构照抄现有页面（组件本体 + 一个 `load()` 构建函数）：

```ts
import { HdsNavDestination } from '@kit.UIDesignKit';

@Component
struct Xxx {
  build() {
    HdsNavDestination() {
      // 内容
    }
  }
}

@Builder
export function load() {
  Xxx()
}
```

2. **注册路由** `entry/src/main/resources/base/profile/router_map.json`：

```json
{
  "name": "Xxx_Page",
  "pageSourceFile": "src/main/ets/pages/Xxx.ets",
  "buildFunction": "load"
}
```

`name` 要和 `pushPathByName('Xxx_Page', ...)` 里的字符串完全一致，`buildFunction` 必须是页面文件里 `export` 出来的那个函数名。

3. **加导航入口**：`Main.ets` 里的 `PageMenu()`。菜单用的受控写法，所以每个 `MenuItem` 里要先把 `isMenuShow` 置 false 再跳转：

```ts
MenuItem({ content: '歌曲列表' })
  .onClick(() => {
    this.isMenuShow = false
    this.navPathStack.pushPathByName('SongList_Page', null, true)
  })
```

## 2. 两页共用的页面骨架

```ts
@Component
struct Xxx {
  @State navPathStack: NavPathStack = new NavPathStack();

  build() {
    HdsNavDestination() {
      // 内容
    }
    .titleBar({ content: { title: { mainTitle: '标题', mainTitleSize: 20 } } })
    .onReady((context: NavDestinationContext) => {
      this.navPathStack = context.pathStack;   // 拿到导航栈，之后要跳别的页就用它
    })
  }
}
```

### 坑 1：HDS 的标题栏是「悬浮」在内容之上的，必须自己让位

如果你不管它，列表第一项会和大标题重叠。让位要加在**滚动容器**上，不要加在内容上：

```ts
Scroll() { /* 或 List() */ }
  .padding({ top: $r('sys.float.single_line_titlebar_height') })
```

- 放在滚动容器上：内容永远在标题栏下方滚动
- 只加在内容上：滚起来之后下面的内容还是会从标题栏底下穿过去

用系统 token 而不是写死数值：手机是 56vp，平板/2in1 那套资源是 86vp，会自动适配。

### 坑 2：V1 下数组/对象必须「整体重新赋值」才会刷新

```ts
// 不会触发刷新
this.selectedIndexes.push(index);

// 正确：造一个新数组再赋值
const next: number[] = [];
// ...填充 next...
this.selectedIndexes = next;
```

### 子组件传参约定

- **静态数据**（歌名、曲线点、颜色）用**普通成员**，父组件构建时传一次，之后不再更新
- **需要跟着父组件刷新的**（选中状态）用 `@Prop`
- **回调**用普通成员 + 箭头函数：`onToggle: () => void = () => {}`
- ⚠️ **自定义组件上不能调 `.width()`、`.layoutWeight()` 这类通用属性**。尺寸要么写在子组件内部根节点上，要么在外面套一层容器（两个页面里都是套 `Column()` 再 `.layoutWeight(1)`）

## 3. 曲线列表页（CurveList.ets）

### 3.1 结构

```
CurveList（页面）
├─ CurveCard：「恒定BPM」，points 为空 → 只有一行字
│    └─ 只显示一个齿轮图标 → 弹自己的「设置默认BPM」输入框
└─ CurveCard × N（ForEach 渲染 CURVES，数据来自磁盘）
     ├─ 标题（左上角）
     └─ Row
          ├─ CurvePreview（Canvas：网格 + 折线 + 标签竖线）
          └─ CardActions()  竖排三个图标
               ├─ gearshape  → 曲线编辑页（onSettings）
               ├─ bookmark   → 标签编辑页（onTags；sys.symbol.tag 不存在，所以用书签）
               └─ trash      → 删除这条曲线（onDelete，带确认弹窗）
```

选中态：整体往左上浮起（`offset(-6,-6)`）+ 阴影加重 + 四周描边（左侧更粗）。

### 3.2 Canvas 画曲线预览

要点：

- `RenderingContextSettings` / `CanvasRenderingContext2D` 每个组件实例一份，写在成员里
- `onReady` 里开始画；`ctx.width / ctx.height` 的单位是 **vp**
- 尺寸可能为 0，先判断再画；`onAreaChange` 里再画一次（尺寸变化时重绘）
- 折线四周留 6vp 内边距，否则线头会被裁掉一半

```ts
private settings: RenderingContextSettings = new RenderingContextSettings(true);
private ctx: CanvasRenderingContext2D = new CanvasRenderingContext2D(this.settings);

build() {
  Canvas(this.ctx)
    .width('100%')
    .height('100%')
    .onReady(() => { this.drawPreview(); })
    .onAreaChange(() => { this.drawPreview(); })
}
```

### 3.3 ⚠️ 最大的坑：选中态的描边**不能改宽度**

错误做法（会造成视觉 bug）：未选中 `borderWidth 0`、选中 `left: 6 / 其他: 1.5`。
因为 **ArkUI 的描边占据组件内部空间**，内容区宽度会从 `W` 变成 `W - 7.5`；而**布局变化是立刻生效的，动画只作用于描边的绘制**，结果就是选中瞬间曲线图右边缘「猛地往里缩一下」。

正确做法：**描边宽度恒定，只切换颜色**，同时用 padding 把描边占掉的宽度补回来：

```ts
.borderColor(this.selected ? this.accentColor : '#00000000')  // 未选中＝全透明，宽度仍然占位
.borderWidth({
  left: CARD_BORDER_LEFT,      // 6
  top: CARD_BORDER_OTHER,      // 1.5
  right: CARD_BORDER_OTHER,
  bottom: CARD_BORDER_OTHER
})
.padding({
  left: CARD_INSET_H - CARD_BORDER_LEFT,     // 16 - 6   = 10
  right: CARD_INSET_H - CARD_BORDER_OTHER,   // 16 - 1.5 = 14.5
  top: (this.points.length >= 2 ? CARD_INSET_V : CARD_INSET_V_TEXT) - CARD_BORDER_OTHER,
  bottom: (this.points.length >= 2 ? CARD_INSET_V : CARD_INSET_V_TEXT) - CARD_BORDER_OTHER
})
```

注意 **ArkUI 的八位色是 `#AARRGGBB`（alpha 在前）**，和 CSS 相反。阴影里的 `'#26000000'` 就是 15% 的黑。

### 3.4 选中动画

```ts
private select(index: number): void {
  this.getUIContext().animateTo({ duration: 220, curve: Curve.EaseOut }, () => {
    this.selectedIndex = index;
  });
}
```

一切会变的属性（offset / shadow / borderColor）都写在状态里，外面套 `animateTo` 改状态即可。

### 3.5 数据来源与刷新

曲线不在内存里写死，而是**一条曲线一个 json** 存在本地：

```
<filesDir>/Curve/1.json     第 1 条曲线（文件名 = 列表里的序号）
<filesDir>/Curve/2.json     第 2 条
```

读写都在 `entry/src/main/ets/ets_libs/CurveStore.ets`，曲线列表、曲线编辑页、标签编辑页三个页面共用。`reloadCurves()` 每次从头读一遍磁盘，顺手把缩略图要的坐标算出来：

- `pointX` / `tagX`：点、标签的归一化横向位置。⚠️ 文件里的 `time` 是**秒**，总长度取最后一个点的时间（分钟），换算统一走 `secToMin()`，别在别处手写 `/60`
- 缩略图上的青色竖线就是标签位置（`TAG_MARK_COLOR`），和标签编辑页保持一致

**⚠️ 最大的坑：刷新不要建在 `pushPathByName` 的 `onPop` 回调上。** 实测在标签编辑页返回时那个回调**不触发**，表现就是"json 明明改了、缩略图不变"。现在的做法是「谁写盘谁通知」：

```ts
// CurveStore.ets：saveAt / appendCurve / deleteAt 写成功之后把版本号 +1
// CurveList.ets：监听它
@StorageLink('curveStoreRevision') @Watch('onStoreChanged') storeRevision: number = 0;
```

写盘 → 版本号 +1 → 列表 `@Watch` 到就重读磁盘，跟用户怎么退出编辑页、`onPop` 有没有触发都无关。另外卡片上的 `points / pointX / tagX` 是**普通成员**，光重读数据不会更新已有卡片，所以 `ForEach` 的键里带了 `listRevision`，让卡片整体重建。

### 3.6 接后端要改的地方

| 现在 | 要换成 |
| --- | --- |
| `@State selectedIndex` | 选中后要通知原生引擎（下发曲线） |
| 曲线只存到磁盘 | 把选中的曲线下发给引擎（见 5.2） |

`CurveData` 是列表页自己的**展示**模型（`title / lineColor / fillColor / points / pointX / tagX`），和落盘的 `CurveFile` 不是一回事：前者只够画缩略图，后者才带 BPM 数据。

## 4. 歌曲列表页（SongList.ets）

### 4.1 交互流

```
音乐库里点某一行 → 加入播放列表（新加入的放最顶部）
                 → 底部悬浮胶囊显示「已选 N 首 · 总时长」
                 → 点胶囊上拉半屏面板
                 → 面板里逐首移除 / 长按拖动排序
```

### 4.2 详情行切成三栏（防止作者名顶掉 BPM）

```ts
Row({ space: COLUMN_GAP }) {
  // 第一栏：作者——唯一可伸缩的，超长自己省略
  Text(this.artist)
    .layoutWeight(1).maxLines(1)
    .textOverflow({ overflow: TextOverflow.Ellipsis })
  // 第二栏：时长——固定宽、右对齐
  Text(durationText).width(DURATION_WIDTH).textAlign(TextAlign.End)
  // 第三栏：BPM——固定宽、右对齐
  Text(this.bpm + ' BPM').width(BPM_WIDTH).textAlign(TextAlign.End)
}
```

作者是唯一会伸缩的，所以再长也只截断自己；时长和 BPM 固定宽度右对齐，**各行竖着对齐成一列**，扫起来很快。

### 4.3 List 的用法

- **淡分割线**用 List 自带的 `.divider()`，不是自己画线：

```ts
.divider({
  strokeWidth: 1,
  color: DIVIDER_COLOR,          // '#F0F0F0'
  startMargin: ROW_PADDING_H,    // 与文字左对齐
  endMargin: ROW_PADDING_H
})
```

- **给悬浮胶囊留空间**用 `.contentEndOffset()`，不要用 padding：

```ts
.contentEndOffset(CAPSULE_RESERVE)   // 只影响可滚动范围，最后一首能滚到胶囊上方
```

用 padding 的话底部会留一条永远滚不到的死区。

- 行是普通行（无圆角无阴影），音乐库那一侧**不是卡片**。

### 4.4 带动画的复选框：用 HarmonyOS Symbol

```ts
SymbolGlyph(this.selected
  ? $r('sys.symbol.checkmark_square_fill')   // 选中：实心方框 + 对勾
  : $r('sys.symbol.square'))                 // 未选：空心方框
  .fontSize(24)
  .fontColor([this.selected ? SELECT_ACCENT : ICON_IDLE])
  .symbolEffect(new ReplaceSymbolEffect(EffectScope.WHOLE), true)
```

- `symbolEffect` 的第二个参数传 **true 而不是 this.selected**：这样「加入」和「移出」两个方向都有动画
- `EffectScope.WHOLE` 是整体替换；`EffectScope.LAYER` 只动单层
- 已验证存在的成对符号：`square / checkmark_square_fill`、`circle / checkmark_circle_fill`、`gearshape / gearshape_fill`、`chevron_up / chevron_down`、`minus_circle`、`checkmark`、`trash`
- 想知道某个名字在不在，去 SDK 里查：`<SDK>/openharmony/ets/build-tools/ets-loader/sysResource.js`（编译器就是拿这张表校验 `$r('sys.symbol.xxx')` 的）

### 4.5 悬浮胶囊 + 上拉面板

```ts
Stack({ alignContent: Alignment.Bottom }) {
  List() { /* 音乐库 */ }
  if (this.selectedIndexes.length > 0) {
    this.PlaylistCapsule()
  }
}
.bindSheet(this.isSheetShow, this.PlaylistSheet, {
  detents: [SheetSize.MEDIUM, SheetSize.LARGE],   // 半屏起，可以往上拉成全屏
  dragBar: true,
  showClose: false,                               // 用面板头部自己的「完成」
  onDisappear: () => {
    this.isSheetShow = false;                     // ⚠️ 必须同步，否则状态会错乱
  }
})
```

`onDisappear` 这行很关键：用户下拉或点遮罩关闭面板时，`isSheetShow` 不会自己变 false，不同步的话下次点胶囊会出现「第一次没反应、第二次才开」。

同样的坑在主页的 `PageMenu`（`bindMenu`）里也遇到过，处理方式一样。

### 4.6 拖动排序：用系统的 `Repeat.onMove`

```ts
Repeat<number>(this.selectedIndexes)
  .each((ri: RepeatItem<number>) => {
    ListItem() { /* 一行 */ }
  })
  .key((songIndex: number) => 'playlist_' + songIndex.toString())
  .onMove((from: number, to: number) => {
    this.moveInPlaylist(from, to);
  })
```

- 走的是**系统拖拽**（自带浮起缩略图和触感反馈），**不要手搓**：手搓要用 `LongPressGesture + onTouch` 自己算位移，拿不到系统的浮层和触感
- `moveInPlaylist` 就是标准的「摘出来再插进去」两次 `splice`，实测上下拖都正确
- 用 `ForEach` 是没有这个能力的，**必须是 `Repeat`**（`RepeatAttribute extends DynamicNode`，`onMove` 才在上面）
- ⚠️ **长按阈值不可配置**：`DynamicNode` 只有两个 `onMove` 重载，`ItemDragEventHandler` 只有 `onLongPress / onDragStart / onMoveThrough / onDrop` 四个回调，`DragInteractionOptions` 里也没有 duration 字段。实测约 500ms。**如果没按够时常按，手指拖动会去拖整个半屏面板**，这是预期行为

### 4.7 时长与总时长

- `SongData.duration` 现在是空字符串 → 界面显示占位符 `--:--`；填上 `'3:42'` 这种格式就自动生效
- 总时长是**真算的**，不是写死的：`totalDurationText()` 里 `parseDuration` 解析 → 累加 → `formatDuration` 还原成 `47:20`；一首时长都没有时才退回占位符
- 总时长现在显示在两处：面板头部 `播放列表　3 首 · 47:20`、悬浮胶囊 `已选 3 首 · 47:20`

### 4.8 接后端要改的地方

**① 歌曲数据源**

`const SONGS: SongData[]` 是写死的演示数据，要换成真实来源。列表一旦变长（几百上千首），`ForEach` 要换成 `LazyForEach`，或者 `Repeat(...).virtualScroll()`——否则会一次性把全部行都建出来。

**② BPM 分析**

原生已经有入口了（`libentry.so` 的 `musicAnalyse(path)`，C++ 侧是 `eb::detect_file_to_csv`），但**它现在返回 void，结果回不到 ArkTS**。要做「列表里显示 BPM」，得先把它改成能回传（见 5.3）。

**③ 播放列表持久化**

现在只存在内存里（`@State selectedIndexes`），退出应用就没了。建议用 `@kit.ArkData` 的 preferences：

```ts
import { preferences } from '@kit.ArkData';

const STORE_NAME: string = 'beat_per_mile';
const KEY_PLAYLIST: string = 'playlist_ids';

async function savePlaylist(ctx: Context, ids: string[]): Promise<void> {
  const store: preferences.Preferences = await preferences.getPreferences(ctx, STORE_NAME);
  await store.put(KEY_PLAYLIST, JSON.stringify(ids));
  await store.flush();
}

async function loadPlaylist(ctx: Context): Promise<string[]> {
  const store: preferences.Preferences = await preferences.getPreferences(ctx, STORE_NAME);
  const text: string = await store.get(KEY_PLAYLIST, '[]') as string;
  return JSON.parse(text) as string[];
}
```

⚠️ **必须存稳定 id（文件路径 / 媒体库 id），不要存数组下标**。现在的 `selectedIndexes` 存的是 `SONGS` 的下标，音乐库一变（新增、删除、重新扫描排序）整个播放列表就全错位了。

**④ 喂给播放引擎**

把选中的歌按顺序交给原生（见下一节建议签名）。

## 5. 接后端：现状与扩展方式

### 5.1 现在的原生接口

`entry/src/main/cpp/types/libentry/index.d.ts`：

| 接口 | 签名 | 作用 |
| --- | --- | --- |
| `audioRendererInit` | `() => void` | 初始化播放器 |
| `audioRendererRelease` | `() => void` | 释放播放器 |
| `music_play` | `(url: string, callback: (progress: number) => void) => number` | 播放，返回播放器 id，进度通过回调回传 |
| `music_pause` | `(id: number) => void` | 暂停 |
| `music_resume` | `(id: number) => void` | 继续 |
| `music_cancel` | `(id: number) => void` | 终止 |
| `changeSpeed` | `(speed: number) => void` | 实时改倍速（C++ 里写进 `dataClip->accelerate`） |
| `musicAnalyse` | `(path: string) => void` | 对音频文件做节拍检测（C++ 里是 `eb::detect_file_to_csv`），**目前不回传结果** |
| `test_audio / add / squire` | — | 早期的连通性测试接口，正式功能别用 |

ArkTS 侧调用：

```ts
import { audioRendererInit, music_play, music_pause, music_resume, music_cancel, changeSpeed, musicAnalyse } from 'libentry.so';
```

### 5.2 界面上「马上要用到」的缺口

| 界面需求 | 现在的状态 | 需要原生提供 |
| --- | --- | --- |
| 歌曲列表显示 BPM | 演示数据写死 | 能回传分析结果的接口 |
| 曲线列表把选中的曲线交给引擎 | 曲线已经落盘，但引擎还拿不到 | 下发曲线的接口 |
| 歌曲列表把播放列表交给引擎 | 只存在内存 | 下发播放列表的接口 |
| 播放界面画进度/步频 | `music_play` 有 progress 回调，但只在测试页用过 | 回调里带 BPM / 步频更实用 |

### 5.3 建议新增的 NAPI 接口（给 C++ 侧）

```ts
// 分析单曲：返回 BPM、节拍点、时长；失败返回 null
export const analyseSong: (path: string) => SongAnalysis | null;

// 下发曲线（恒定 BPM 模式传一个点即可；points 是 [时间秒, BPM] 数组）
export const setTempoCurve: (points: number[][], smooth: boolean) => void;

// 下发播放列表
export const setPlaylist: (paths: string[]) => void;

// 运行状态回传（步频、当前 BPM、命中率）
export const setTempoCallback: (cb: (cadenceBpm: number, musicBpm: number, hitRate: number) => void) => void;
```

C++ 侧现成可用的东西：`CppDataAnalyzer.hpp` 的 `Paragraph` 段落结构（含 `bpm_start / bpm_trend / bpm_at_time(t)`）、`TempoFollower.hpp` 的步频跟随状态机（倍速上下限、命中率、平滑 τ）、`LiveStretchPlayer.h` 的 `setSpeed / play / pause / seekTo`。

### 5.4 加一个 NAPI 接口的三步

1. `entry/src/main/cpp/napi_bridge_center.cpp` 里写静态函数：

```cpp
static napi_value Xxx(napi_env env, napi_callback_info info) {
    size_t argc = 1;
    napi_value args[1] = {nullptr};
    napi_get_cb_info(env, info, &argc, args, nullptr, nullptr);
    // 取参数（字符串用 napi_get_value_string_utf8）
    // ... 业务 ...
    // 要回传就 napi_create_xxx + return result，不需要回传就 return nullptr
}
```

2. 在 `desc[]` 里注册（用 ArkTS 侧要用的名字）：

```cpp
napi_property_descriptor desc[] = {
    // ...
    {"xxx", nullptr, Xxx, nullptr, nullptr, nullptr, napi_default, nullptr}
};
```

3. 在 `entry/src/main/cpp/types/libentry/index.d.ts` 里补类型声明 —— **漏了这一步 ArkTS 会报找不到模块/类型**。

## 6. 待办与已知限制

| 项 | 说明 |
| --- | --- |
| 时长数据 | 还没有来源，界面统一显示 `--:--`，填上 `'3:42'` 即生效 |
| 颜色全部写死 | 两个页面里的颜色都是十六进制字面量，**暗色模式还没做**。要支持的话应该把颜色提进 `resources/base/element/color.json` 与 `resources/dark/...` |
| 大列表性能 | 音乐库现在是 12 首演示数据；上百首后要换 `LazyForEach` / `Repeat.virtualScroll` |
| 拖动排序长按阈值 | 系统拖拽约 500ms，**API 层不可配**，没按够可能变成拖面板 |
| 循环开关没持久化 | 曲线 json 里没有 `isLoop` 字段，编辑页里关掉循环不会存下来 |
| 曲线没法下发给引擎 | 保存只到磁盘（见 3.6） |
| 播放列表「清空」没做 | 属于破坏性操作，要配确认弹窗 |
| 播放列表没持久化 | 只存在内存（`@State selectedIndexes`），见 4.8 ③。**曲线本身已经落盘了** |
| 页面导航顺序未定 | `PageMenu()` 里现在是「曲线列表 / 歌曲列表 / 曲线编辑 / 播放器 / 标签编辑」，顺序随时可调 |
